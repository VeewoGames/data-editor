# 文档字段与技能节点合同

## 概述

### 1. 总体目标和范围

文档字段让数据记录关联项目内 Markdown 内容；技能节点合同则为正式技能数据提供可校验的结构约束。两者都在编辑前建立明确边界，避免把任意文本或任意 JSON 当成受保护的结构化内容。

### 2. 各阶段任务概要

1. 在 `ViewConfig` 中为数据文件声明文档根目录与字段启用状态。
2. 在详情面板读取并渲染关联 Markdown。
3. 编辑正式技能节点时读取合同、携带版本/etag/save token 并由服务端校验保存。

### 3. 整体结构框架

```text
view-config -> documentFiles / documentFields -> document-index/content -> Markdown detail panel
skills.json -> skill-node-contract -> validated save -> source file
```

## 文档字段

项目级 `view-config.json` 的 `documentFiles` 为数据文件指定 `docRoot`，`documentFields` 用 `<file>:<collection>:<field>` 键启用具体字段。服务通过 `/api/document-index` 列出可解析文档，通过 `/api/document-content` 读取受限于 `docRoot` 的内容；详情面板以只读 Markdown 渲染。

文档根目录和数据字段都属于项目共享语义。文档字段只负责关联和浏览，不会把 Markdown 内容写回 JSON/CSV，也不会把任意文件暴露到数据源边界之外。

## 技能节点合同

正式技能数据保存前，前端从 `GET /api/skill-node-contract` 获取项目范围的合同版本、etag 与 save token。保存时，`POST /api/save` 必须携带这些值；服务端重新检查合同是否仍一致，并拒绝缺失、过期或不满足合同的保存。

合同机制只保护受识别的正式技能文档路径；普通 JSON/CSV 仍按通用保存链路处理。其目的不是替代数据编辑器，而是把高风险技能节点的结构验证放到写回源文件之前。

## 使用边界

- 文档字段需要显式配置，不会根据文件名自动猜测并写入配置。
- Markdown 以只读方式展示；其编辑权仍属于相应的文档工作流。
- 合同校验是保存时的强约束，不是 UI 层的提示性规则。
