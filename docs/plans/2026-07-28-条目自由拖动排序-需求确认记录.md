# 条目自由拖动排序需求确认记录

## 方案概述

### 1. 总体目标和范围

为 Data Editor 的主表条目提供可见、可控且可持久化的上下拖动排序能力。排序改变的是业务文件中数组条目的源顺序，而不是个人布局或团队共享视图的临时顺序；成功后沿用现有自动保存和 `documentEtag` 陈旧写保护。

本轮同时将现有常驻“删除行”图标替换为行级拖拽把手。点击把手打开条目操作浮框，首版提供复制与删除；删除仍必须经过二次确认。

本记录只确认产品需求与边界，不授权代码、数据、测试或配置实施。

### 2. 各阶段任务概要

1. **源顺序重排**：为真实数组 collection 增加基于稳定 `rowId` 的重排操作，并接入现有 `mutate`、自动保存与 ETag 保护。
2. **表格交互替换**：将常驻删除控件改为拖拽把手，统一承载点击菜单与拖动排序两种意图。
3. **条目操作菜单**：提供复制条目与删除条目；删除沿用现有确认对话框。
4. **状态门禁与验证**：在搜索、筛选、字段排序状态禁用拖动，并覆盖长列表自动滚动、选中保持与保存冲突。

执行顺序为先定义源数据重排与状态门禁，再接入表格手势和菜单，最后完成定向测试与真实交互验证。

### 3. 整体结构框架

```text
数组 collection 的主表行
  -> 拖拽把手
     -> 点击（未超过移动阈值）
        -> 条目操作浮框
           -> 复制条目
           -> 删除条目 -> 二次确认 -> 现有删除链
     -> 按住移动（超过约 4px）
        -> 以 rowId 定位源数组条目
        -> 在源数组中重排
        -> mutate -> dataDirty -> autosave -> documentEtag
```

## 一、已确认需求

1. **排序权威**：拖动排序直接修改业务文件内数组条目的源顺序，所有用户与运行时消费者读取同一顺序；不新增个人视图或共享视图排序真值。
2. **支持范围**：首版支持根数组和顶层数组 collection；不支持 `record-map`、嵌套数组。
3. **视图门禁**：当存在搜索、筛选或字段排序时，禁用条目拖动；只有默认源顺序可排序。
4. **稳定定位**：排序以 `rowId` 定位被拖动条目与落点，禁止以当前可见行号或 `sourceIndex` 作为最终写回身份。
5. **入口替换**：移除“显示行删除控件”及其常驻删除图标；每行改为固定拖拽把手。
6. **把手手势**：点击把手打开浮框；按住并移动超过约 4px 后进入拖动排序；未移动松开仍打开浮框；Escape、点击外部、放下或取消按各自语义关闭/结束。
7. **浮框功能**：首版只提供“复制条目”和“删除条目”。删除不改变现有二次确认与写回保护。
8. **长列表体验**：拖动指针进入表格上下边缘约 48px 时自动滚动，越接近边缘越快；离开边缘、到达尽头、放下或取消立即停止。
9. **选中与反馈**：重排后保持原条目选中，并给出已调整顺序及保存状态反馈。

## 二、明确不做

- 不为个人 profile 或团队共享视图保存独立条目顺序。
- 不允许在搜索、筛选或字段排序结果中拖动。
- 不支持 `record-map` 或嵌套数组的条目排序。
- 不将删除改成无确认的一键操作。
- 首版不承诺触屏排序、键盘排序或跨 collection 拖动。

## 三、已核实项目事实

- 主表的 `visibleRowIds` 是源顺序经过搜索、筛选和字段排序后的结果；因此屏幕顺序不能直接作为源数组落点。
- `DocumentStore` 已维护稳定 `rowId`，现有编辑与删除支持按该身份写回。
- `mutate` 会标记 `dataDirty`、刷新数据与表格 revision，并调度业务文档自动保存；保存请求携带并更新 `documentEtag`。
- 现有删除行操作已使用 `ConfirmDialog`，可保留为浮框菜单中“删除条目”的后续确认步骤。

## 四、验收标准

1. 默认源顺序下，可把任意支持范围内的条目拖到另一条目前或后，并在重新打开文件后保留顺序。
2. 拖动后仍选中原条目，不会错改相邻条目。
3. 搜索、筛选或字段排序生效时，没有可用的拖动排序入口。
4. 点击把手可打开包含复制与删除的浮框；删除必须显示二次确认。
5. 长列表可以通过边缘自动滚动完成跨可视区域的排序，取消后立即停止。
6. 文档 ETag 过期时，排序保存不得覆盖更新后的外部文件。

## 五、开放问题

无。触屏、键盘可访问性与跨 collection 拖动明确不在首版范围内，后续如需支持应单独立项。
