# G4 夜曲知识配置迁回执行计划

## 概述

本计划将 G4 分为事实冻结、候选准备、专项确认、正式发布与验收五章。目标是把 11 份项目知识和 5 份混合文档中的业务归属交回夜曲，保留编辑器通用合同；不改变当前项目配置、玩法数据和历史非重放保护。

第一章已经完成只读调查；第二章只能在方案获准后制作隔离候选；第三章是正式执行前必须停下的确认门。第四、五章是确认后的实施蓝图，不能据本计划直接执行。当前 40 路径白名单尚无完整 after SHA，不是正式执行包。索引命令若在隔离预演失败，停在检查点，补充原因与后续计划，不编造已通过。

方案正文见 `2026-10-25-G4夜曲知识配置迁回方案.md`；全部 source/target/before SHA 与引用见 `docs/records/2026-10-25-G4夜曲知识配置迁回核实/`。

## 第 1 章：冻结事实与保护边界（本轮调查完成）

目标：给每份材料确定 owner、当前状态和是否需要写入。范围是当前知识、已声明历史记录及配置入口；不扫描接管无关任务或修改状态。输出为两份 JSON 清单、只读 G3 postchecker 结果及双仓 scoped Git 状态。完成条件为所有候选都有来源摘要和处置，没有依赖旧验收数字补签。

### 1.1 子计划：当前来源与目标对账

输入：G0/G1 清单、G3 正式报告、当前两仓知识与实际配置。输出：31 份知识判定、16 源映射、18 配置保护项、25 Markdown/4 JSON 历史文档分类、1 旧示例处置。排除游戏机制重新评审、个人 profile 复制和现行规则改写。

- **1.1.1 来源完整性**：扫描全部当前 Truth/ADR；登记 path/SHA/size、heading、入出引用并与 G0 比较。验证 100 扫描、31 判定及 11/5/14/1 分类。文档状态和章节继承状态尚未逐段解析，明确留待2.1.3，不把标题清单等同状态核验。发现新来源不按文件名自动迁移，先判定。
- **1.1.2 当前 authority 对账**：逐项确认现行预算、评审、描述生成、共享配置 owner，记录冲突与已覆盖事实；六份已有 Night owner只读。新业务决定不在调查中落库。
- **1.1.3 配置消费者核实**：确认 18 现存配置原位、旧示例无运行时消费者、现行 manifest 是 `.data-editor/project.json` + enrollment；不得复制旧 schema。输出 G5 候选，G4 零配置写入。

### 1.2 子计划：保护与协作基线

输入：G3 postchecker、现有配置和 Git 状态。输出：当前只读保护结果及范围限制。

- **1.2.1 运行保护复核**：只读检查 generation 1、209 目标、433 原件+10 声明变化、73 源副本、12 run/36 拒绝。失败记录差异，不修补旧证明或恢复业务。
- **1.2.2 协作范围记录**：保存当前候选及保护路径 dirty 状态；现有改动不归本任务。Night 超长 untracked 路径采用 scoped status + tracked status 说明覆盖限制，不全局改 Git 设置。
- **1.2.3 规划复核**：架构与只读复核，处理本轮文档发现；产出待用户确认的方案，不动正式知识。

## 第 2 章：制作隔离候选（等待方案批准）

目标：把 40 路径提案变成可审阅的完整内容包。依赖：用户批准推荐范围。成果：全文 payload、分段补丁、完整摘要、原生索引隔离报告和恢复矩阵。非范围：正式仓库迁移、服务运行、业务程序和数据库手工编辑。

### 2.1 子计划：承接内容与状态后像

输入：刷新后的来源清单与现行 owner；输出：16 原字节 payload、manifest、historical 索引、11 historical 源说明、5 generic/split 后像及其余已列定向修改。

- **2.1.1 刷新精确前像**：对全部 40 目标核 before/不存在条件，核源与六份 current owner、18 配置和全部保护基线；检查真实物理路径与别名。漂移阻断包，不改变 expectedDigest。
- **2.1.2 原字节与归属回执**：准备 `<sha>.source` 与 manifest，逐一绑定 16 源、接收路径和当前规则 owner。校验全文字节，不把 raw Markdown 当 current 检索正文。
- **2.1.3 内容分段**：先登记官方文档状态、章节状态与继承结果；再逐段标 retain-current-generic / historical-project / already-covered / conflict，准备源说明和五份混合文档后像，保留通用合同覆盖证明。被重写的 Truth/ADR 修复为官方结构，通用正文分别 current/accepted，项目历史显式 history；11 整体退出源为 document-state historical。Targeting 的业务字段集合与旧 token 形状一并标为历史，不能只删项目名。任何新游戏规则或额外写路径需重新决策。
- **2.1.4 引用与中立示例**：准备已冻结两份入引用文档、双仓 SUMMARY、两份产品说明的最小补丁；验证普通链接、纯文本引用与新锚点。冻结任务和原证明不重写。

### 2.2 子计划：隔离发布与检索检查点

输入：完整内容副本和已安装 CLI；输出：原生发布命令、before/after 查询日志和失败恢复试验。只在本轮独立目录写，不能污染 live `.claw/memory.sqlite`、项目配置或服务 registry。

- **2.2.1 原生索引预演**：遵守 Night ADR0262，在独立副本先验证受支持的一致性数据库备份与恢复，再演练两仓 `claw search index --refresh`、状态解析与别名查询。列出原生索引、WAL/SHM、工具管理日志/元信息、备份的独立写入边界和目录；40项仅内容目标，完整文件效果分母待此检查点后确定。记录当前 help 的后台 deferred 诊断是否影响刷新。没有可靠备份、无法隔离、未知写入或诊断未闭合时停在此处，补充后续计划并复核，不操作 live 索引。
- **2.2.2 失败与重试试验**：模拟仅部分原字节接收、源已退出但索引失败、目标并发修改；证明 create-only/CAS 拒绝未知字节，已有 Night current owner 始终不变，重试不覆盖外部输入。
- **2.2.3 内容与保护对比**：比对内容候选恰好 40 项、18 create/22 replace/0 delete；原生索引及备份只在另列派生边界写入，其他目标零写入；所有 `.data-editor`、业务、Profile authority、证据与当前 Night规则不变。若内容40项不足或工具效果越界，更新提案、说明增量并重审，不能静默扩大。

## 第 3 章：冻结精确包与正式执行确认（强制确认门）

目标：让用户批准可逐项检查的实际内容。依赖：第二章全部出口通过。成果：冻结索引及摘要、清晰的写集、恢复路径和独立复核。此章完成前不能实施第四章。

### 3.1 子计划：交付确认包

- **3.1.1 冻结执行物**：列出全部内容路径/action/before SHA/after SHA/payload SHA、源原字节、分段内容与状态、链接、逐项 receipt、精确顺序和真实命令。内容写集、工具管理索引及一致性备份分表，完整文件效果范围据预演冻结；禁止活跃 SQLite 直接复制恢复，已有内容或其他写者变化时不盲目恢复旧索引。
- **3.1.2 再次独立复核**：检查 11+5 覆盖、六份 current owner 不变、通用能力解释保留、Claw 合法状态、入引用、保护排除和中断恢复；发现必须修改的内容后重算完整摘要再复核。
- **3.1.3 用户正式确认**：展示范围、内容摘要、命令、暂时不一致窗口和恢复限制，等待明确批准此冻结包。包 stale、内容/目标变化或用户仅批准方案时，不能正式执行。

## 第 4 章：按确认包发布（仅供批准后实施）

目标：完成知识归属退出；保留当前规则与所有数据。前置：用户确认第三章冻结包且紧邻执行复核无漂移。范围仅批准路径；无服务停机、物理删除或业务动作。

### 4.1 子计划：先接收后退出

- **4.1.1 接收来源**：在真实目标 create-only 写入 16 原字节与 manifest，逐一 fsync/摘要核验；同字节可识别为已接收，异字节立即停。仅有磁盘材料不代表迁回完成。
- **4.1.2 发布历史接收索引**：CAS 写 historical 索引和 Night SUMMARY，通过原生刷新与检索确认历史可达；既有六份 current owner不动。失败时源不退出。
- **4.1.3 发布源后像**：每次读当前字节并 CAS 替换为确认后的历史说明/混合后像、引用与中立示例；每项写后核 SHA、记回执。源不存在或未知字节停止，不能盲目重放整批。
- **4.1.4 刷新编辑器检索**：使用原生索引命令，逐项检查 current/historical、目标 owner 和原别名。失败保留内容与日志，G4 不完成；不直接清库、改 metadata 或借业务配置“修复”。

## 第 5 章：验收与收尾（仅供批准后实施）

目标：证明知识已归位且保护未变。依赖：内容与索引发布完成。成果：逐项迁回报告、保护核验和 G5 剩余清单，不包含 commit/push。

### 5.1 子计划：逐项可达与保护

- **5.1.1 知识验收**：对 16 源完成题名/别名/主题三组查询和已登记链接校验；11 源不再作为当前规则，5 混合保留通用 current；Night当前规则仍为既有 owner，不新增重复权威。
- **5.1.2 保护验收**：对本轮刷新保护集核前后 SHA，复跑只读 history/authority 检查与 36 拒绝；配置/业务有合法外部更新时保留新输入、分类并停止未授权覆盖，不恢复旧目录。
- **5.1.3 收尾记录**：写逐项结果、剩余风险、健康只读结果、Git scoped diff；G5 旧示例删除、旧目录与此前被拒清理项仍未执行。若本轮意外启动过服务/Browser 或做过 stop/shutdown，必须按 AGENTS 执行 service:finalize 并明确报告；正常知识迁移不需要为收尾启动服务。

验收未通过只标具体项 pending，不把部分接收、文件存在或检索能连通冒充 G4 完成。
