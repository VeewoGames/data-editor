# 项目列表管理方案

日期：2026-10-24。状态：已实施，并在隔离与正式服务完成验收；结果见[实施与验证记录](../records/2026-10-24-项目列表管理实施与验证记录.md)及[发布证明升级与正式验收](../records/2026-10-24-发布证明承接升级与正式验收记录.md)。正文保留设计合同，实际验证以记录为准。

## 一、问题、边界与不变量

### 方案概述

目标是让用户维护左上角的本机项目列表：添加已有项目目录、主动移除有效或无效的注册项、自由调整顺序，并在刷新和重启后保留顺序。产品保持通用，不引入具体项目的业务规则。

整体由三个部分组成：项目管理交互、注册表持久化、页面工作区安全过渡。按“确认并同步合同 → 完成注册表写入边界 → 接入管理界面 → 验收”推进；各阶段分别产出明确规则、可验证 API、可操作界面和运行证据。详细任务与验收见第四节。

用户已明确采用：**允许主动移除有效项目，但至少保留一个项目。** 本轮仅形成方案及优雅性复核，不实施代码、不修改真实项目注册表、不自动提交或推送。

### 需求与非目标

| 功能 | 本期行为 |
|---|---|
| 添加 | 复用现有名称、根目录输入；新增项目排末尾，成功后打开；重复目录复用已有项且不改变其位置 |
| 移除 | 用户可主动取消任意注册项，但最后一项不能移除；保留所有磁盘文件、业务数据与配置 |
| 排序 | 拖动手柄任意排序，提供上移、下移；完成一次移动即保存 |
| 切换 | 普通下拉仍承担快速选择；排序及移除非本页当前项目不切换工作区 |
| 持久化 | 同一服务注册表的所有页面共用顺序；不承诺不同设备或不同 registry home 同步 |

不包含：删除磁盘项目、项目分组/收藏/置顶/搜索、批量移除、自动清理无效项目、空项目首页、跨设备同步、通用资源管理框架、改变现有默认项目选择机制。

### 已核实事实与约束

- 添加界面和 API 已存在；注册按根目录查重，新项追加末尾。[App.tsx](../../src/App.tsx#L1332)、[project-registry.mjs](../../src/project-registry.mjs#L48)
- 移除 API 已存在，仅更新 registry；移除默认项后取剩余第一项，禁止删除最后一项。[server.mjs](../../server.mjs#L738)
- 下拉直接按 `projects` 数组展示，规范化也保留该数组顺序；无需引入第二份顺序。[Sidebar.tsx](../../src/components/Sidebar.tsx#L133)、[project-registry.mjs](../../src/project-registry.mjs#L84)
- 浏览器本页当前项目可由 URL 指定，并不等同于 registry 的 `activeProjectId`；普通选择只改变本页 URL 和状态。[App.tsx](../../src/App.tsx#L960)、[App.tsx](../../src/App.tsx#L1301)
- 旧 accepted ADR 仅允许证据证明无效或误注册后清理。这与用户本次采纳的主动移除有效项目存在适用范围冲突；实施前须同步更新规则，不能假称现有合同已支持。[原清理 ADR](../../.claw/truth/adr/project-registry-and-view-profile-cleanup-policy.md#L15)

不变量：项目 ID、根目录和配置不因排序改变；失败不得伪装保存成功；移除不得清理文件或配置；当前项目过渡被阻止时不得发送移除请求、修改列表或 URL。

## 二、新增或改变的概念、唯一 owner 与数据流

### 职责与唯一事实来源

| 事实或职责 | 唯一归属 | 界面允许保留的状态 |
|---|---|---|
| 项目集合、默认项目和排列 | 用户级 `projects.json`，由 `src/project-registry.mjs` 管理修改 | 已确认 registry 快照 |
| 本页当前项目 | 现有 URL 与 App 工作区状态 | 不因排序覆盖为服务端默认项 |
| 管理操作 | App 协调 API 与编辑过渡；管理对话框展示和发出意图 | 拖动预览、待处理确认、请求中、错误 |
| 注册表 HTTP 接口 | `server.mjs` 解析参数并调用注册表操作 | 不复制排序、查重、至少一项等领域规则 |

注册表位于 `projectRegistryPath()` 返回位置，默认 Windows 为 `%APPDATA%/data-editor/projects.json`；继续尊重 `DATA_EDITOR_HOME` / registry home。顺序使用现有 `projects` 数组；不新增 `order` 字段、localStorage 顺序或 profile 排序配置。[路径与保存](../../src/project-registry.mjs#L10)

### 界面结构

1. 保留普通下拉选择和现有 `+`；下拉底部增加“管理项目”。
2. 管理对话框列出拖动手柄、名称、根目录、当前标记、上移/下移和“从列表移除”。顶部提供“添加项目”，复用现有添加弹窗。相同名称靠路径区分。
3. 首项禁用上移，末项禁用下移；只剩一项时禁用移除，提示“至少保留一个项目”。服务端仍独立执行同一限制。
4. 仅手柄启动拖动，拖动不触发项目选择。上下移使用可聚焦按钮，操作后保持焦点并播报新位置；取消拖动不提交。沿用现有对话框关闭与焦点恢复方式。
5. 管理操作或添加正在提交时，禁用重复修改并保持模态，拒绝 Escape、外部点击或关闭按钮退出；避免请求等待期间继续编辑旧工作区。请求完成后恢复关闭能力，失败保留原工作区。此处为实施代码复核后的编辑保护修正。

### 最小 API 合同

复用添加、更新、移除、激活接口，新增 `POST /api/projects/reorder`，请求体仅为 `{ projectIds: string[] }`；返回提交后的完整 registry。项目列表管理写入响应统一提供提交结果，避免写入成功后还必须依赖额外 GET 才能确认本次结果。

排序必须在写入边界内读取最新 registry，验证请求是当前 ID 集合的完整排列，拒绝重复、未知和遗漏的 ID；只重排服务端已有对象，不接受客户端整份项目配置。集合已变动返回冲突，前端重新加载并提示重试；纯顺序并发以最后一次成功提交为准。相同顺序重复请求视为成功，无需单独幂等键或持久化版本号。

移除沿用 `{ projectId }`；不存在目标明确报错，最后一项明确拒绝；删除默认项时由服务端选剩余第一项。前端不能把响应中的默认项无条件覆盖本页仍有效的当前项目。[现有 client](../../src/api/client.ts#L549)

所有 registry 的读取—修改—保存必须共享同一窄修改入口，包括添加、更新、移除、默认激活、启动注册和排序；单独给 `save` 排队无法避免旧快照覆盖。[现有读改写](../../src/project-registry.mjs#L48)、[服务端写入](../../server.mjs#L721)

实施前先核实正式服务是否允许多个进程共用 registry。若有该支持场景，应复用项目内可用的文件互斥能力保护完整读改写；若没有，先维持单写服务边界。不得未经检查就新增通用跨进程锁框架，也不得把进程内队列宣称为跨进程保护。该检查是后端切片的首个检查点。

## 三、推荐决策、关键理由与一个关键失败路径

### 已采纳与推荐细节

- **普通选择与管理分开**：降低切换时误拖、误移除的机会，不把现有项目设置或自动化设置改造成综合管理中心。
- **主动移除有效项目**：确认框显示名称及完整根目录，并说明“仅从列表移除，不会删除项目文件”。更新旧 ADR，明确用户主动取消注册适用该规则；代理主动清理历史坏项仍要求原三重证据。同步 Truth，不混入业务数据删除协议。
- **至少保留一个项目**：沿用现有服务端限制，不增加空态、启动空表或永久隐藏项目机制。
- **直接保存数组顺序**：无需 schema 迁移；既有数组顺序就是上线后的初始顺序。移动只影响列表排列，不激活项目。

### 添加和当前项目移除的过渡

添加成功后打开新项目，因此应在发送添加请求前检查当前编辑是否可安全离开。当前项目移除同样先完成移除确认，再提交编辑草稿并等待保存协调结果；仅 `saved` 或 `idle` 可继续。`blocked-confirmation`、`error`、`deferred` 等结果均停止操作，保留草稿、列表与 URL，提示先解决编辑问题；本期不增加“强制放弃”分支。复用已有 `flushBeforeDocumentTransition()` 的结果门槛，不直接复制当前 `selectProject()` 只等待 Promise 的做法。[过渡守卫](../../src/App.tsx#L1443)

添加取消或守卫不通过时不发送请求。重复根目录不新增注册项、不移动其位置；添加成功后按返回结果更新列表和本页工作区。移除非当前项不触发本页编辑过渡。移除本页当前项成功后，选择提交结果中剩余第一项、清理旧项目 URL 上下文，再加载对应工作区；不在提交后再次弹出可取消的离开确认。

若服务器已提交但新工作区加载失败，列表仍反映已提交结果，展示加载错误并允许重试或选择其他项目；不能回滚显示已被移除的注册项。项目相关迟到请求不得覆盖新项目工作区，此项需验证现有异步加载是否已有身份检查，仅在缺失时补足。

### 关键失败路径：旧排序覆盖新添加

页面 A 显示 `[P1, P2]`，页面 B 添加 `P3`，页面 A 提交 `[P2, P1]`。服务端在统一读改写边界读到 `[P1, P2, P3]` 后拒绝 A 的旧集合排序；前端刷新为服务端列表，提示“项目列表已变化，请重新排序”。`P3` 必须保留。若两个页面只调整相同集合，允许后提交覆盖先提交的顺序，省去本期并不需要的 revision 协议。

确定失败时撤销本地拖动预览；网络中断导致提交结果未知时，先读回 registry 核实，不盲目重发，也不直接宣称回滚。读回仍失败则显示“保存结果待确认”，暂停后续管理修改，保留最后已确认快照；重新连接后校准。

其他页面移除了本页正在打开的项目时，在本页下一次 registry 刷新或项目操作发现失效后，保留本地草稿并阻止继续向失效项目发起新操作，提示重新添加或另选项目；不自动切换并丢弃编辑。本期不新增实时广播或轮询服务，不承诺立即跨页面通知。

### 启动语义与风险边界

显式以项目目录启动或嵌入式启动仍代表打开该项目，启动初始化可重新注册已移除目录；本期不增加隐藏名单。普通启动如何推导 root 继续沿用原规则，不承诺“移除后任何启动方式都不会再出现”。[默认 root](../../src/default-project-root.mjs#L5)、[初始化注册](../../server.mjs#L278)

移除不停止既有后台任务、不删除运行记录，也不承诺取消运行中任务；实施前确认后台任务是否依赖后续 registry 查找，若移除会使既有任务无法完成，应先提出针对性处置方案，再决定允许移除或临时禁用，不擅自新增取消协议。真实文件受外部修改影响、多个进程写入和异步工作区迟到响应均属于需要定向验证的风险，不视为已验证故障。

## 四、最小实施切片、验证与关键引用

### 分阶段执行结构

本节是方案内的实施拆解，不是已启动的执行任务，也不建立第二份 Claw 生命周期。

| 阶段 | 目标、范围与依赖 | 成果及完成条件 |
|---|---|---|
| 1. 合同与检查点 | 以已确认需求为输入；核查注册表多进程写者、运行中任务对 registry 的依赖、工作区异步身份检查 | 明确最小支持边界；同步原 Truth/ADR 的主动移除规则；存在新实质取舍先报告决策，不编造后续实现 |
| 2. 注册表与 API | 依赖阶段 1；集中现有 mutation，增加排序及完整结果响应 | 测试证明无丢项、保持至少一项、排序不改项目配置；不改真实用户注册表 |
| 3. 管理交互 | 依赖 API；新增小型管理对话框，复用添加弹窗与编辑过渡 | 拖动与上下移一致，取消/保存失败均安全，当前项目移除后的 URL/工作区一致 |
| 4. 集成验收 | 依赖前三阶段；使用隔离 registry 和测试目录 | 覆盖下方验收矩阵；记录真实鼠标与键盘操作证据，清理仅本任务测试资源 |

每个阶段的原子动作：

1. **合同阶段**
   - 定向核实服务启动/写入者与后台任务依赖，记录结果；若影响移除许可或互斥策略，先补充最小修订再执行后端任务。
   - 在 `.claw/truth/project-registry-and-view-profile-cleanup-boundary.md` 与对应 ADR 区分用户主动移除和坏项治理，保留磁盘删除边界；检查两份规则一致。
2. **后端阶段**
   - 在 `src/project-registry.mjs` 提供窄的读改写入口并迁入相关规则，所有现有调用改走该入口；复核启动入口没有旁路。失败保持原文件，不保留旧写机制作兼容分支。
   - 在 `server.mjs` / `src/api/client.ts` 接入排序与提交结果；增加隔离注册表测试。若集合校验或并发测试失败，先修写入边界，不接界面掩盖。
3. **界面阶段**
   - 在 `src/components/Sidebar.tsx` 增加管理入口，使用独立项目管理组件及必要样式，复用现有图标、对话框和合适的拖动基础能力；不引入通用管理框架或业务数组行操作规则。
   - 在 `src/App.tsx` 组织添加/移除过渡、排序结果、URL 和异步身份；覆盖无 model 和正常 workspace 两个现有渲染分支，避免重复两套操作逻辑。
4. **验收阶段**
   - 执行有意义的 registry/API 与状态过渡测试，再验证真实界面。测试失败保留证据并修复，不把静态检查通过当完整验收。
   - 若启动服务、浏览器或临时验证资源，按项目约定运行 `npm run service:finalize`，核验 8787/8791 health，浏览器回到正式 URL，并记录临时进程、目录清理结果。

### 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 添加有效目录 / 重复目录 / 无效目录 | 新项末尾且打开；重复不新增不重排；无效目录不写入 |
| 拖动、上移、下移及取消拖动 | 两种移动得到同一顺序；取消不提交；刷新及重启保留顺序 |
| 移除后显式以该目录启动 / 普通启动 | 前者允许重新注册并排末尾；后者沿用默认 root 推导；既有项目相对顺序保持，不将重新注册误判为排序丢失 |
| 排序不变性 | ID、root、dataSources、filePolicy 与本页当前项目不变 |
| 移除非当前项 / 当前项 | 前者不切换；后者先过编辑守卫，提交后 URL 和新工作区一致 |
| 仅一项 / 两页并发移除 | 服务端拒绝最后一项；并发不能产生空列表 |
| 有编辑改动且 flush 被阻止或失败 | 不发送添加/当前项移除请求，不丢草稿、不改 URL |
| 移除文件保护 | 根目录、业务文件、项目配置及运行记录未因移除被删除 |
| 添加或移除与旧排序并发 | 不丢项目，不复活已移除项；集合变化拒绝旧排序 |
| 两次纯排序 / 更新与排序并发 | 前者最后成功提交生效；后者不覆盖配置更新 |
| 网络中断 / 写失败 / 新工作区加载失败 | 读回核实不确定结果；不假成功；已提交列表不被错误回滚 |
| 同名项目 / 键盘操作 / 两种 workspace 分支 | 路径可辨认、按钮可聚焦、操作后焦点稳定；所有分支入口行为一致 |
| 其他页面移除本页项目 / 迟到加载 | 检测后保留草稿、停止失效新操作；旧响应不覆盖新工作区 |

### 优雅性复核记录

复核日期：2026-10-24。独立架构复核结论：通过；独立 `recheck` 优雅性专项复核结论：通过。没有发现阻断性的需求遗漏或已确认的过度设计。复核基于文档及定向代码证据，未执行运行验证；复核不等于实施授权。

采用的精简：保留单一 `projects` 数组，复用添加弹窗、移除 API、编辑过渡守卫和对话框基础；不增加第二份排序、持久化 revision、隐藏名单、实时广播或通用管理/锁框架。纯排序最后成功提交生效，集合变化才拒绝旧排序。

必须保留的复杂度：完整读改写边界、`saved/idle` 过渡门槛、已提交结果与拖动预览分离、网络结果未知时读回核实。这些分别保护并发正确性、编辑内容和界面状态真实性，不应为缩短代码而删除。

复核唯一可选补充已采纳：验收矩阵增加移除后显式启动重新注册与普通启动的语义，防止误读“重启保留顺序”。跨进程写者、后台任务依赖和迟到响应仍作为第一阶段检查点，不宣称已验证。
