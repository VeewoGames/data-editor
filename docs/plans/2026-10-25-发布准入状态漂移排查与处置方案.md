# 发布准入状态漂移排查与处置方案

## 概述

本方案处理G5正式清理预检发现的`C:/Code/Nocturnel/.data-editor/publication-admission/state.json`漂移：查清实际差异、现有写入机制和历史运行保护影响，再确定恢复G5资格的最小路线。范围仍只有既定的1个旧样例和2个条件空目录，不扩大为产品重构或数据修复。

整体结构分为事实与边界、处置选择、阶段与门禁、验证和确认点。本轮完成只读取证与方案复核；用户采纳后才允许另行准备隔离后继候选；新候选须冻结完整写集、摘要、命令和恢复路径，再取得正式执行确认。任何阶段出现未知差异或无法建立静默，均保持停止。

本轮只新增本文及私有取证材料，不回写旧publication状态、不修改产品或现行配置、不改旧冻结包/摘要、不重试清理。没有生产SQLite连接或HTTP请求，没有启停服务或操作Browser。

## 2. 问题、owner及不变量

publication状态是现有准入owner管理的活动状态。revision是并发/CAS令牌，即使它单独变化也不能称为可随意回退的无用字段。回写旧状态可能倒退并发令牌、抹掉真实预约，违反现行ADR对保留最新publication的要求（`.claw/truth/adr/project-generality-and-external-deployment-authority.md:19,39,60`）。

G5清理器只拥有删除样例和两个空父目录的许可，不拥有重写publication、历史ledger、authority、业务或配置的权限。私有取证记录不成为新的生产authority。

旧包的拒绝有两层：G5的`guards.mjs::verifyProduction`绑定该文件旧SHA，同时调用原G4的`execute-content.mjs`；后者`:21,24`也运行旧`protectedCheck`。只改G5一个摘要仍会被旧G4拒绝，吞掉该错误则会掩盖其他保护失败。

必须保留：旧G3/G4/G5包、原始证明、备份和失败回执；反别名及单硬链接检查；全部非目标数据和通用能力；旧run拒绝；create-only恢复与未知输入保留。不得用项目名判断或建立项目专属产品逻辑。

## 3. 处置选项与推荐

### A. 一次性G5后继核验候选（推荐，尚未获准准备）

3. 在上述条件下复制新的完整publication字节作为后继候选的精确前像并固定完整SHA。与旧冻结字节逐段核对，仅接受本次明确复核的revision前进；任何其他字段、未知字段、状态、generation、预约、包成员或绑定变化均转为新问题，不能自动接受。
4. 新只读核验链保留原G4的包/工具/安装树及索引来源检查，并对40项正式后像、payload/restore、全部保护及G3原件/authority/12run拒绝作完整核验。对唯一publication路径采用明确审查的新前像；其他原保护保持原严格值。不能修改旧G4保护表或执行器，也不能直接吞掉旧`protectedCheck`的错误来伪装原验收通过。

## 4. 阶段、依赖与验收

### 阶段一：本轮只读排查与方案复核

成果为精确字节差异、主服务观察预约归因、完整只读保护结果、本文及独立架构/recheck记录。完成条件是将原始差异、动态现场和未知的原始调用者分开陈述，保留所有禁止写入边界。完成后等待用户选择A/B或另案C，不准备/冻结后继执行包。

### 阶段二：用户采纳A后，隔离准备后继候选

输入是本轮审查方案、旧G4/G5固定包和新的只读现场。输出为私有快照、明确的唯一差异承接合同、完整新核验链及隔离回归，不写正式目标。静默建立方式须先核实；若确需服务/前端操作，先明确具体控制对象、操作副作用与收尾要求，未获准不得停服务、暂停其他任务或重置状态。

核验器需复用现有包/索引验证函数，补齐无法复用部分的等价证据，不伪称原G4全量after命令通过。先在未持publication锁时让既有观察完成；不能持锁等待continuation归零，因为结算本身也需要同一锁。锁内发现仍有预约应退出释放，不强制清除或原地等待。

按现有owner约束验证锁顺序；不能跨子进程长持同一project锁后再spawn会重新取锁的checker，进程内AsyncLocalStorage的重入条件不能跨进程继承。完整子进程预检在未持这些锁时完成，最终短窗口采用已核实的同进程只读路径；获取锁前后状态不同则停止。隔离资格须证明锁释放、既有结算能完成、父子检查无等待环，超时不解释为成功。合作锁不等于OS全局排他，不能替代真实写者静默。

最低资格覆盖：此次原始字节重构；唯一已审查revision差异；任意其他字节/字段/类型/别名变化拒绝；状态、generation、accepted、continuations、package变化拒绝；新前像后续revision变化拒绝；其他保护漂移拒绝；旧包/历史证据原件保持；跨层G4依赖和903源集完整；12run/36拒绝不变；1文件与2空目录动作及create-only恢复边界。不得把诊断投影比较当资格放行逻辑。

遇新增差异，停止并修订待审方案，不自动扩充承接列表。准备完成后冻结新包，展示精确写集、完整摘要、执行与恢复命令、静默窗口及服务副作用，等待新的正式确认。

仍只处理`examples/nocturnel/data-editor.project.json`，随后非递归移除两个空父目录；新增只读核验和任务审计不获得生产state写权限。执行前再次核对全部包、来源、备份、历史消费者、保护、静默和物理路径。失败保留现场，不自动续作或回滚。

### 阶段四：验收与恢复路径核验

检查三个目标后像、全部非目标严格绑定、publication新前像、G3闭锁与G4内容/索引来源/实际备份；保留回执和原件。实际恢复仍另行确认，只create原样例及必要父目录，不恢复业务、索引、runtime、publication或authority快照。若未来启停服务触发AGENTS的service:finalize，需事先将主health可能产生revision变化纳入执行边界，不能事后更新摘要掩盖它；本轮没有这类操作。
