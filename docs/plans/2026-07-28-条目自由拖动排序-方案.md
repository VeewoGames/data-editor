# 条目自由拖动排序与行级操作菜单方案

## 方案概述

### 1. 总体目标和范围

本方案将主表条目排序收敛为源数组顺序的通用编辑能力：所有真实数组 collection 都可在默认视图中拖动行级把手，系统按稳定 `rowId` 重排数组，再复用既有 `mutate → autosave → documentEtag` 链路保存。它不新建个人或团队视图的条目排序配置，也不维护项目或文件白名单。

同一把手还承担条目操作入口：点击打开浮框，首版提供复制与删除；删除继续经过既有二次确认。拖动排序只覆盖根数组与顶层数组 collection；`record-map` 不可排序但仍保留复制与删除。嵌套数组、触屏/键盘排序或跨 collection 拖动不在本轮范围内。

### 2. 各阶段任务概要

1. **模型层**：提供只适用于真实数组 collection 的 `rowId` 重排 primitive，并返回足以恢复选中状态的结果。
2. **编排层**：在 `App.tsx` 将 rowId 重排接入 `mutate`，声明排序能力与搜索/筛选/字段排序门禁。
3. **表格层**：以把手替换常驻删除控件，实现点击菜单、阈值拖动、落点预览和边缘自动滚动。
4. **验证层**：覆盖数据重排、门禁、选中保持、复制/删除菜单、ETag 冲突与真实浏览器交互。

### 3. 整体结构框架

```text
DataTable
  -> RowActionHandle
     -> click: RowActionPopover
        -> duplicate -> App duplicate handler -> mutate/autosave
        -> delete -> existing ConfirmDialog -> existing delete handler
     -> drag: RowDragController
        -> rowId source + target rowId + before/after
        -> App reorder handler
           -> reorderRowsByRowId(model, collectionPath, sourceRowId, targetRowId, placement)
           -> mutate -> DocumentStore rebuild -> selectedRowId retained
           -> POST /api/save with documentEtag
```

## 一、现状与问题

`DataTable` 当前仅在每行首列提供可选显示的常驻删除图标。该图标既占用空间，也不能承载复制等后续行级操作。主表的可见行则经过源顺序、搜索、筛选与字段排序计算，因此当前可见索引不具有可安全写回源数组的含义。

现有 `DocumentStore`、`writeback-adapter` 与保存链已经提供稳定 `rowId`、源条目定位、`mutate` 调度和 `documentEtag` 陈旧写保护；缺少的是“按两个 rowId 重排真实数组”的模型操作，以及表格层的拖拽协议。

## 二、方案设计

### 1. 源数组重排是唯一排序真值

新增模型层重排函数，输入 `model`、`collectionPath`、源 `rowId`、目标 `rowId` 与 `before | after` 落点语义：

- 先拒绝 `record-map`、未知 collection、非数组 collection、相同条目与缺失 rowId。
- 通过现有 store/writeback 的 rowId 定位能力解析当前源数组位置。
- 对原数组本身执行一次安全的移除和插入，不克隆或重建条目对象。
- 输出移动后的 source index 与 rowId，供 App 保持选中。

`sourceIndex` 和屏幕 `visibleRowIndex` 只可作为瞬时渲染信息，禁止充当最终写回身份。

### 2. 排序能力门禁

`App.tsx` 统一计算 `canReorderRows`，并传入 `DataTable`：

- collection 必须是根数组或顶层数组；所有满足该数据形状的 collection 一律适用，不按文件、项目或玩法用途额外配置启用名单。
- 当前 query 为空。
- 当前 filters 为空。
- 当前 sorts 为空。
- 不处于 command saving、关闭、重启或重建等现有受控状态。

不满足时把手仍可点击打开操作菜单，但不进入拖拽态；菜单中的复制和删除不受排序门禁影响。

### 3. 把手与操作浮框

现有 `row-action-cell` 改为固定宽度的 `RowActionHandle`：

- 小位移点击打开 Radix `Popover`，菜单项为“复制条目”“删除条目”。
- 指针移动超过约 4px 后关闭/不打开菜单并进入拖动。
- 浮框菜单中删除只调用现有 `onDeleteRow`，继续使用 `ConfirmDialog`；不在浮框内直接删除。
- 复制通过新的 `onDuplicateRow` 进入 App：
  - 数组 collection：深拷贝源条目，移除旧 `__entry_id` 和运行时行身份，在源条目之后插入，再生成新 `__entry_id` 并选中新副本。
  - `record-map`：深拷贝源条目后交给现有 map 新增路径生成新 key；不人为写入 `__entry_id`，同样选中新副本。
  - 若 collection 已配置主键/唯一字段，副本在插入前按现有自动后缀规则生成未占用的新值（如 `fireball` 变为 `fireball_2`）；原条目及既有引用不改写。
  - 两种复制都走 `mutate`，不得让嵌套对象或数组被原条目与副本共享引用。
- 彻底删除 `showRowDeleteControls`、`rowDeleteControlsVisible`、`TableSettingsPopover` 的对应 props/checkbox、相关 ViewTabs 快照字段、`.row-delete-hidden` 样式及其源文本测试，不保留旧兼容入口。

### 4. 拖拽与长列表

`DataTable` 保持自己的拖拽临时态，不把预览顺序写入业务数据：

- 拖拽态仅保存源 rowId、当前目标 rowId、`before | after`、指针位置与预览信息。
- 仅在 pointer up 且落点有效时调用 `onReorderRows`；Escape、pointer cancel、离开有效区域时不写数据。
- 靠近表格滚动容器顶部或底部约 48px 时，基于 `requestAnimationFrame` 自动滚动；距离边缘越近速度越快。
- 每次实际滚动后重新计算落点，避免浏览器未补发 pointer move 时沿用旧目标。
- 首版只响应鼠标/精确指针拖动；触屏不会进入排序拖动。键盘可聚焦并点击打开操作菜单，但不提供键盘排序。

### 5. 状态一致性与保存失败

重排和复制均使用 `mutate`。DocumentStore 重建后按既有 `selectedRowId` 恢复当前条目，而不是依赖旧 index。保存成功后更新 `documentEtag`；保存失败时保留本地顺序或副本及 dirty 状态，显示现有错误反馈。若服务返回陈旧 ETag，不自动重放排序或复制写入；用户刷新或处理冲突后再继续操作，确保不覆盖外部修改。

## 三、验证策略

1. **模型单测**：数组重排的 before/after、首尾、同一条目、无效 rowId、record-map 拒绝、持久 `__entry_id` 与对象引用保持；数组复制的新身份与深拷贝、主键自动后缀（文本、数值与连续后缀），以及 record-map 复制生成新 key。
2. **编排单测**：`canReorderRows` 对 query、filters、sorts、collection 形状和受控保存状态的门禁；重排后选中保持。
3. **组件合同测试**：把手替换旧删除控件；新增回调被 `DataTable` memo 比较器纳入；点击与拖动阈值不串扰。
4. **浏览器测试**：默认视图拖动、长列表边缘滚动、Escape 取消、操作浮框复制/删除、确认删除和重开文件持久化。
5. **保存冲突测试**：使用陈旧 `documentEtag` 的重排或复制保存返回现有冲突结果，不覆盖外部文件，并保留本地 dirty 状态且不自动重试。

## 四、风险与非目标

- 数组顺序可能影响运行时内容消费；这是通用编辑器对“调整源数组顺序”作出的显式数据编辑，使用者应像修改任意字段一样在内容层面判断是否要执行。编辑器不维护项目或文件白名单，也不推断玩法语义。
- 拖拽仅在默认源顺序开放，避免筛选或排序视图中的落点语义歧义。
- 不在本轮合并批量 `saveDocuments()` 的 ETag 语义、触屏/键盘可访问性或跨 collection 迁移；这些是独立范围。
