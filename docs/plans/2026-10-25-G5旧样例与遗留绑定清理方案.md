# G5 旧样例与遗留绑定清理方案

## 方案概述

总体目标是移除当前工具检出中已经退出、没有现行消费者的夜曲旧样例，防止它继续被误抄为第二种项目配置；保留通用能力、真实项目选择、夜曲业务和现行配置、所有迁移备份及历史非重放保护。G5不追求“夜曲/legacy字样零命中”，不把历史证据或测试夹具当产品绑定。

分四阶段推进：A本轮完成清单、消费者和保护核实；B经方案确认后仅准备隔离候选、恢复副本和精确执行包；C待用户再次确认该包后才正式清退；D只读验收并核验恢复路径。结构如下：事实清单→推荐边界→执行与失败合同→保护/恢复→验收与确认。

**本轮状态：规划与复核，未执行清理。** 完整逐项清单见[保留矩阵](../records/2026-10-25-G5旧样例与遗留绑定核实/完整候选与保留矩阵.md)及同目录G5完整核实清单.json；任务证据位于C:\Code\data-editor\.claw\tasks\2026-10-25\G5旧样例与遗留绑定清退规划。

## 4. 阶段、执行合同与关键失败路径

A已核实G4后像/保护与G3闭锁；本轮完成方案和复核后停在确认门。B才允许构造任务私有原字节副本、一次性清退manifest和隔离预演：固定1文件+2目录的前像/后像或状态，冻结全部脚本/保护/工具摘要并列明实际命令和恢复命令。**本文件不是已冻结执行包，也不是正式删除批准。**

C执行前再次验证候选摘要、真实物理路径、无reparse/junction/多硬链接、完整目录成员及新消费者；实际建立目标编辑者静默条件。复用既有比较/合作锁边界，不宣称hash+删除是OS原子CAS。不能保证非合作写者静默时不执行。先验恢复副本再删除单文件，随后仅空目录API移除父目录；使用[System.IO.Directory]::Delete(path,false)等失败即停的空目录语义，禁止-Recurse、通配符、git clean、跨shell拼接删除或绕过策略拒绝。

关键失败：冻结后有人向examples/nocturnel加入文件，或将目录换成junction。前置成员/物理视图检查必须在任何删除前拒绝。若文件删除后才并发加入新内容，非递归空目录删除应失败；保留新内容与逐项回执，不视为完整成功，不扩大清理，也不自动复原或覆盖输入。

其余失败：摘要变化/保护交集/未知消费者→零写入停止；恢复副本损坏→不删；策略拒绝→停止并记录，不尝试其他shell/改名绕过；部分执行→记录实际状态，只读核验后另审精确续作或恢复。不存在新长期authority或自动垃圾回收器。

删除样例不改变源码、构建输入、现行配置、部署requiredFiles或Claw记忆源，因此推荐不重建dist、不停启服务、不注销项目、不打开生产DB、不刷新索引、不改Truth。实际发现需要这些动作时退出本切片并补范围确认。

D最小验收：唯一文件不存在；两目录为已批准的不存在/空目录状态，没有未知内容被删；其他同域文件与全部保护保持；G440后像/756保护、903索引来源、G3 generation1/209目标/12旧run的36闭锁拒绝继续通过。读取现有proof或只读配置不代替需要时的真实运行测试；后续候选阶段按消费者证明选择最小隔离回归，不因清理而启动真实服务。

恢复以任务私有已校验before副本为输入：验证工具root与各级父目录物理身份，仅在批准路径无文件时以create-only写回；已是相同摘要可幂等跳过，出现不同字节/未知文件/alias立即停止。只恢复此1文件和必要空父目录；不回滚registry、业务、runtime、索引或authority。全部before和迁移原件继续保留，不因“验收通过”自动清除。
