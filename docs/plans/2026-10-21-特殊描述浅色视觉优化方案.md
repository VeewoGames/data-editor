# 特殊描述浅色视觉优化方案

## 方案概述

目标是让动态数值、`{关键词}`、`[关键词]` 在浅色界面中一眼可分，同时保持正文连续阅读和现有编辑体验。范围仅为 Data Editor 的描述展示：表格浏览、表格编辑、详情编辑；不修改作者源文、已验文案、项目机制、关键词身份、生成器或游戏 Tooltip。

整体采用“三种轻量强调、一套公共样式、同源识别”的结构。先完成格式盘点与静态视觉稿，再统一浏览和编辑的类型识别及样式，最后验证显示一致性和编辑回存不变量。用户于 2026-10-21 明确采用蓝色无边框方案并要求走 Claw 开始实施；该授权不包含提交、推送、覆盖生产构建或重启后端。

## 一、当前类型与问题

### 1. 统计口径与结果

2026-10-21，只读核对编辑器解析入口及当前 Nocturnel 的七个已配置源文字段，包含现有历史条目，共 **301 行、602 个语言字段**。下表计数是中英文合计的标记出现次数，不是不同关键词或数值的数量，也不代表全部处于启用状态。

| 类型 | 源文形式 | 当前显示 | 出现次数 |
| --- | --- | --- | ---: |
| 动态数值/表达式 | `<value ref="…">可读内文</value>` | `<+20%>`、`<6% 生命上限>` | 738 |
| 默认关键词 | `<kw id="…" mode="default">…</kw>` | `{关键词}` | 108 |
| Alt 关键词 | `<kw id="…" mode="alt">…</kw>` | `[关键词]` | 194 |
| 效果片段 | `<effect ref="…">…</effect>` | 标签隐藏，内容正常显示 | 132 |
| 消耗/代价分段 | `<cost>…</cost>` | 标签隐藏，内容正常显示 | 6 |

因此是 **4 类标签、5 种角色：3 种主要可见强调 + 2 种结构容器**。数值可能包含百分比、单位或复合表达式，视觉上仍归同一类，不按物理/法术/增益/减益继续分色。

还有四类需保护的状态，而非四种新业务类型：缺可读内文、自闭合旧 value；结构损坏或标签不闭合；转义后显示的字面标签；尚未获得稳定引用的作者新输入。当前盘点的 602 个字段中，自闭合旧 value、转义标签及裸 `{…}`/`[…]` 均为 0，但既有编辑器测试要求继续保护这些输入。未知标签家族未发现。此统计不等于完整语法有效性检查。

正式产物的 `<val id="…" mode="auto" />` 是生成/运行时形式，不是当前可读源文控件中的第六种强调类型；不改高级字段的原始数据展示。普通正文和多语言切换也不另算特殊格式。

证据：`src/detail/inline-template-dom.mjs:16–26`；`inline-template-text.mjs:8–12`；项目 `.data-editor/inline-template-config.json`；项目编译器 `parseAuthorSource()`。完整分文件盘点保存在本线程的 `description-format-inventory.json`。

### 2. 已确认问题

- 所有数值与两种关键词共用深褐底 `#463B28`、金字 `#FFDC91`，在白底表格中重量过大，也无法靠样式辨认类型。
- 同一套颜色分别硬编码在编辑 DOM 和表格浏览 JSX 中，后续容易不同步。
- 浏览先转换为纯文本，再通过 `<…>` / `{…}` / `[…]` 正则染色；编辑则按真实源文标签识别。普通括号或转义文本可能只在浏览态被误染。不能只把两处颜色分别替换。
- 效果与代价容器保留身份、隐藏标签，本身没有醒目的色块；不应因本轮盘点把它们升级为另外两种胶囊。

项目内 `{关键词}` 与 `[关键词]` 的现有含义分别关联默认解释卡和 Alt 追加解释卡。这个差异来自项目规则，Data Editor 只区分已有 `mode`，不新增游戏浮框行为，也不把 Alt 关键词变成禁用或不可编辑状态。

## 二、推荐视觉方案

### 1. 三种浅底色，保留括号

| 类型 | 浅背景 | 深文字 | 视觉意图 |
| --- | --- | --- | --- |
| 动态数值 `<…>` | `#EAF2FF` | `#2157A5` | 浅蓝，区分可计算参数，不表达增益或正负效果 |
| 默认关键词 `{…}` | `#FFF3D6` | `#805800` | 柔和琥珀，较强的关键词识别 |
| Alt 关键词 `[…]` | `#F1EDFA` | `#67509A` | 淡紫，区别于默认关键词 |

以浅色背景为主，文字保持足够深。三类仍用 `< >`、`{ }`、`[ ]` 区分，颜色不是唯一识别方式。以上为视觉方案色值，实际同屏验收可以微调明度，不改类型映射。

推荐几何：圆角 3px、左右内边距 2–3px、上下不增加 padding、字号和行高继承正文、字重 500。按用户最新要求，三种正常强调均移除细描边，不使用投影、立体按钮感或很圆的标签形状。主体保持 `display:inline`、继承换行；长表达式可随正文换行，避免 `inline-block` / `nowrap` 把长句撑出单元格。

设计预览曾提供动态数值的绿色/蓝色本地切换，绿色对照为浅底 `#EAF6EC`、深字 `#27633D`。对比后用户确定采用蓝色；其他两类样式固定不变。不将设计预览切换器引入产品设置、数据字段或新的实施范围。

保留当前括号，不新增箭头、图标、“动态数值”等文字到 token 内部。不改变选中背景或原生焦点表现，不新增点击动作和悬浮解释系统。

### 2. 结构与诊断

- 效果片段和代价分段：默认透明，保留当前文字布局及结构身份；不插入“效果”“代价”标签，不为了好看改变分段内容。
- 缺可读源文：显示既有的“缺可读源文：ref”文字，配浅红警示背景/细虚线边界，不能伪装成正常蓝色数值；原始自闭合标记回存保持原样。
- 结构损坏：沿用现有 effect/cost 边界损坏时整段原文回退；其他未识别片段保留原文，旁边的有效 token 仍按现有合同识别，不扩展为完整语法校验。如添加诊断，只能放在不可序列化的控件外。
- 未绑定的括号文本和转义字面标签：本切片按普通作者文字保留，不自行推断成绑定对象。显式生成仍由项目程序处理。
- 正常浅底色只表达类型，**不表示已经校验、与机制一致或正式生效**。目前 `data-template-pending` 只是“有内文”，不得据此画成功/失败状态。

本轮以浅色主题作为主要视觉验收。现有深色主题不能被白底硬编码破坏：公共样式采用语义 CSS 变量并在现有主题选择器中提供对应值；深色回归仅保证可读和身份一致，不扩展为主题重设计。

## 三、职责边界与推荐实现

唯一持久化事实仍是原始源文及其 `ref` / `id` / `mode`。颜色、圆角和边界完全属于 Data Editor 展示层，不写回 JSON，也不增加项目配色配置。

复用现有 `templateNodes(source)` 作为浏览和编辑的共同源文识别路径：表格浏览通过一个小型只读展示封装构造节点，替代先纯文本化再按括号重猜类型；搜索继续使用现有 `readableTemplateText()` 纯文本投影。不要引入完整新 AST、另一套解析器、项目程序调用、标签缓存或新的服务端 API。

样式由 `src/styles.css` 中局部作用域内的语义变量和选择器维护。复用现有 `data-template-ref`、`data-template-keyword-mode` 等身份；编辑与只读节点共享样式。移除两处深褐金内联样式，其余 DOM 身份、contentEditable、选择和序列化合同保持。

数据流：源文 → 现有源文识别 → 带身份节点 → 公共浅色样式；编辑回存仍由现有 serializer 处理；生成校验路径不变。

关键失败路径：如果为区别类型向节点内部插入“数值”文字或图标替代文本，serializer 直接读取 `textContent`，装饰可能成为作者文字。故本轮只用 CSS 改外观，不增加会进入序列化的子节点；主题或 hover 变化也不能重建正在编辑的 DOM。

涉及文件预期为 `src/detail/inline-template-dom.mjs`、`src/detail/InlineTemplateField.tsx`、`src/styles.css` 与相关模板测试。`TextCellSurface` 的现有点击编辑、选择、换行和省略合同继续复用；只有定向验证证明需要时才调整调用参数，不先改全局表格行为。

不修改 Nocturnel 文件、生成器、数据或游戏颜色，不处理当前独立连接恢复的四个工作区修改，也不主动 commit、push、重启服务或创建 Worktree。
