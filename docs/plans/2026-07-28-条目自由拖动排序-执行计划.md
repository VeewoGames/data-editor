# 条目自由拖动排序与行级操作菜单执行计划

## 方案概述

### 1. 总体目标和范围

本计划实施通用的主表条目排序和行级操作菜单：所有真实数组 collection 都可在默认源顺序下拖动重排；把手点击提供复制和删除；`record-map` 仅保留复制和删除。所有数据修改复用 `rowId`、`mutate`、自动保存和 `documentEtag`，不创建第二套排序配置，也不维护项目或文件启用名单。

实施不覆盖嵌套数组排序、触屏/键盘排序、跨 collection 移动或批量保存协议重构。数组顺序是显式可编辑的数据内容；编辑器不按项目或玩法语义限制该通用能力。

### 2. 各阶段任务概要

1. **先建纯模型能力与单测**：确保源数组重排、复制深拷贝、主键后缀和 record-map 行为可独立证明。
2. **接入 App 编排与保存状态**：以 rowId 调用模型能力，声明排序门禁，保持选中与现有保存失败语义。
3. **替换 DataTable 行控件**：实现把手、菜单、拖动、长列表自动滚动并清理旧删除开关。
4. **完整验证与交接**：跑定向测试、真实浏览器交互、ETag 冲突用例并报告验证边界。

### 3. 整体结构框架

```text
Phase 1: model/writeback primitives + unit tests
  -> Phase 2: App handlers + save/selection tests
  -> Phase 3: DataTable handle/popover/drag + component tests
  -> Phase 4: browser E2E + ETag conflict + final checks
```

## 一、实施前门禁

1. 检查工作树，明确本任务仅拥有模型、表格、App、样式、测试与本计划文件；不得覆盖无关改动。
2. 确认普通文档保存仍经由 `/api/save` 和 `documentEtag`，不将本任务扩展到 `saveDocuments()` 批量保存协议。

## 二、分阶段执行任务

### Phase 1：模型与稳定身份

**目标文件**：

- `src/document-model.mjs`
- `src/model/writeback-adapter.mjs`
- `src/model/document-store.mjs`（仅在必要时补导出或合同）
- 对应 `tests/document-model.test.mjs`、`tests/document-store.test.mjs`、新增 focused test

**任务**：

1. 新增仅适用于真实数组 collection 的 `reorderRowsByRowId`：解析源/目标 rowId，验证落点，原地移动数组元素，返回移动结果。
2. 明确拒绝 `record-map`、非数组、缺失 rowId、相同 rowId 与无效落点。
3. 复制能力按现有职责拆成两层：
   - `document-model` 的纯数据操作只接收源 locator 与 `primaryKeyField`，完成深拷贝和插入，并返回新条目的 `{ sourceIndex, sourceKey }`；它不接收 store，也不生成 `rowId`。
   - `writeback-adapter` 的 `duplicateRowByRowId({ model, store, collectionPath, rowId, primaryKeyField })` 先把源 rowId 解析为 locator，调用纯数据操作，再以旧 store 为 previous store 重建 DocumentStore，按新 locator 解析并返回 `{ rowId, sourceIndex, sourceKey }`。
   - 数组：`structuredClone` 可序列化内容，移除 `__entry_id`，插入源行之后，生成新 `__entry_id`。
   - 已配置 `primaryKeyField`：调用现有 `resolveAutoSuffixedPrimaryKeyValue` 生成未占用值；不改写原条目或 relation。
   - record-map：深拷贝后走 map 新增路径，获得新 key；不写 `__entry_id`。
4. 证明副本与原条目的嵌套对象/数组没有共享引用，且重排不克隆原条目。

**完成条件**：

- 根数组与顶层数组的 before/after、首尾移动均通过。
- record-map 重排失败且不改数据；record-map 复制/删除仍可用。
- 新副本身份、主键后缀、深拷贝和插入位置均通过测试。

### Phase 2：App 编排、状态与保存

**目标文件**：

- `src/App.tsx`
- 必要时 `src/model/writeback-adapter.mjs`
- focused App/state tests

**任务**：

1. 增加 `handleReorderRows`、`handleDuplicateRow`，只通过 rowId 调用模型层能力，再调用 `mutate`。
2. 计算通用的 `canReorderRows`：真实数组、无 query、无 filters、无 sorts，且不在 command saving/关闭/重启/重建状态；不得加入 file、project 或玩法语义白名单。
3. 将 `canReorderRows`、排序、复制、删除回调传给所有 `DataTable` 渲染路径，并把新增回调纳入组件 memo 比较。
4. 重排后依据 rowId 保持选中；复制后选中新副本。
5. 保存成功更新 ETag；失败时维持本地数据及 dirty。陈旧 ETag 不自动重试或自动重放。

**完成条件**：

- 搜索、筛选、字段排序、record-map 或受控状态下排序入口不可用。
- 重排/复制后选中状态正确；ETag 冲突不覆盖外部文件、不清 dirty。

### Phase 3：把手、菜单与拖拽

**目标文件**：

- `src/table/DataTable.tsx`
- 视复杂度新增受控 `src/table/row-dnd.mjs` 或 `RowActionHandle.tsx`
- `src/components/ViewTabs.tsx`
- `src/components/TableSettingsPopover.tsx`
- `src/styles.css`
- 相关组件/合同测试

**任务**：

1. 用固定行级把手替换常驻删除图标；点击打开 Radix Popover，菜单显示“复制条目”“删除条目”。
2. 指针移动超过约 4px 才进入拖动；点击、Escape、pointer cancel、点击外部按既定语义关闭菜单或取消拖拽。
3. 仅鼠标/精确指针允许排序；触屏不启动排序。键盘可访问把手菜单，但不提供键盘排序。
4. 用 source rowId、target rowId 与 before/after 表达拖放意图；pointer up 前不写业务数据。
5. 在表格滚动容器上下约 48px 实现 rAF 边缘自动滚动，并在每次滚动后重新计算落点。
6. 删除 `showRowDeleteControls`、`rowDeleteControlsVisible`、ViewTabs snapshot/props、TableSettingsPopover checkbox、`.row-delete-hidden` 和对应测试断言。

**完成条件**：

- 常驻删除图标和设置开关零残留。
- 点击把手只打开菜单，拖动只在有效落点写入一次。
- 长列表可跨可视区域拖动，取消和到边立即停止滚动。

### Phase 4：验证与收口

**任务**：

1. 运行新增/修改模型、adapter 与组件合同测试：`node --test tests/document-model.test.mjs tests/document-store.test.mjs tests/writeback-adapter.test.mjs tests/view-engine.test.mjs tests/view-state.test.mjs`，再运行 `npm run typecheck`。
2. 运行 `npm run test:e2e`；它使用 Playwright 的独立 scratch server，不能将其结果等同于正式 `8787` 服务的验证。
3. 使用真实浏览器验证：默认排序拖动、浮框复制/删除、删除确认、筛选/排序禁用、长列表自动滚动、Escape 取消和重开文件持久化。
4. 在正式服务启动或 Browser 验证时，验证完成后运行 `npm run service:finalize`；最终报告 `http://127.0.0.1:8787/api/health`、`http://127.0.0.1:8791/health`、正式 URL `http://127.0.0.1:8787/` 及临时进程/目录清理结果，并使 Browser 停留在正式 URL。
5. 运行陈旧 ETag 保存冲突用例，确认不覆盖文件且保留 dirty。
6. 运行 `git diff --check`；报告构建、定向测试与浏览器验证的各自边界，不用静态检查替代运行时验证。

## 三、验证矩阵

| 场景 | 期望结果 |
| --- | --- |
| 默认数组视图拖动 | 源数组顺序改变，重开后保持 |
| 搜索/筛选/字段排序 | 无可用排序拖拽入口 |
| 数组复制 | 深拷贝、新 `__entry_id`、主键自动后缀、选中新副本 |
| record-map 复制 | 新 key、无排序、可删除 |
| 删除 | 菜单触发确认，不会一键写入 |
| 长列表 | 边缘滚动且落点持续更新 |
| Escape / pointer cancel | 无业务数据写入 |
| ETag 陈旧 | 不覆盖外部文件、保留 dirty、无自动重试 |

## 四、交接与授权边界

本执行计划经用户审批后，仍须通过 `claw plan start` 创建具体实施任务并进入 `process.active`，才构成实施授权。排序能力是对真实数组 collection 的通用编辑行为，不设置项目、文件或玩法语义启用门。
