# 方案概述：左侧边栏 Notion 风格折叠与顶部项目栏

## 一、总体目标、范围与结构

本方案为 Data Editor 增加可隐藏的左侧边栏，并将项目名称、项目切换入口与隐藏箭头置于侧栏顶部。交互借鉴用户提供的 Notion 参考图的信息层级，但保持现有 Data Editor 的明暗主题、颜色 token、紧凑控件尺寸与无品牌图标边界。

范围包括：应用壳层的侧栏显隐状态、展开/恢复入口、展开态顶部两行布局、状态持久化、无障碍语义、克制动效及自动化/人工验收。范围不包括：项目品牌资产设计、键盘快捷键、窄窗口自动折叠、View Profile 数据结构迁移，以及现有文件树与项目管理功能的语义调整。

整体结构为：

```text
App（唯一显隐状态与布局 authority）
├─ Sidebar（展开态项目栏、管理按钮与既有文件树）
├─ sidebar-resize-handle（仅展开态存在）
├─ Workspace / Toolbar（正常模型态的收起态固定恢复入口）
└─ Empty-state workspace header（无模型/加载态的同语义恢复入口）
```

执行顺序：先建立 `isSidebarCollapsed` 的独立持久化与 App 布局切换，再扩展 Sidebar/Toolbar 的控制入口，随后完成样式与动效，最后补齐测试和浏览器验收。

## 三、现状与职责边界

### 3.1 已核实入口

- `src/App.tsx` 持有 `sidebarWidth`，通过 `appFrameStyle` 注入 `--sidebar-width`，并渲染 Sidebar、分隔条与 Workspace；它是显隐状态和 grid 切换的唯一 authority。
- `src/components/Sidebar.tsx` 已拥有项目下拉菜单及三个管理入口，适合只负责展开态顶部两行结构，不应持有全局显隐状态。
- `src/components/Toolbar.tsx` 是正常模型态的 Workspace 顶部工具栏，适合承载收起态固定恢复按钮；`!model` 分支没有 Toolbar，必须额外提供同语义的空态 workspace header，避免持久化收起后刷新到加载态时无入口恢复。
- `src/styles.css` 的 `.app-frame` 当前为三列 grid，`.sidebar-resize-handle` 是独立 grid 项；两者必须同时切换，不能只用 `display: none` 隐藏内容后保留 6px 轨道。
- 现有 `sidebarWidth` 既会存入 View Profile，也会回退到 localStorage；本需求的显隐状态必须刻意与它分离。

### 3.2 状态 authority

新增独立布尔值 `isSidebarCollapsed`，推荐 localStorage key：`data-editor:sidebar-collapsed`。

- 初始值：读取 key；仅字符串 `"1"` 视为收起，缺失或其他值视为展开。
- 写入：用户点击展开态收起按钮或收起态恢复按钮时立即写入。
- 生命周期：刷新、项目切换、View Profile 加载/重置都不得覆盖该值。
- 非目标：不得把它加入 `UserViewProfile`、本地视图状态或 shared view；不得令其造成 `profileDirty`、`viewDraftDirty` 或保存提示。
- 宽度：继续沿用现有 `sidebarWidth` 的读写与 Profile/local view 回退规则；收起时不删除、不重置、不写入宽度，恢复时使用之前的宽度。

## 四、目标交互与布局

### 4.1 展开态

侧栏保持现有文件树、拖拽重排、项目切换菜单与三个管理操作的功能语义。顶部区域变为两行：

1. 第一行 `.project-switcher` 为整行浅色圆角项目条：左侧为项目名与下拉箭头，右侧为收起按钮（双左箭头图标）。项目名可截断，收起按钮有独立可访问名称“收起侧边栏”。
2. 第二行 `.project-management-actions` 放新增项目、项目设置、自动化设置三个现有按钮。保留直接访问，避免把确认过的 B 方案退化为菜单内操作。
3. 点击收起按钮：先关闭项目菜单，再将 `isSidebarCollapsed` 设为 `true`；不触发项目切换、数据保存或 Profile 修改。
4. 拖拽分隔条只在展开态渲染；收起时不得留有可命中、可聚焦或可拖动的残余元素。

### 4.2 收起态

1. `.app-frame` 从三列切为单列，Workspace 占满横向剩余空间；侧栏和 resize handle 从 DOM 中条件渲染，而非仅视觉隐藏。
2. Toolbar 最左侧放图标按钮（双右箭头），`aria-label` 与 tooltip 均为“展开侧边栏”；它在收起态始终存在，不依赖文件、项目或 View Profile。
3. `!model` / Loading 空态使用同一套 `onExpandSidebar`，在空态内容上方提供样式一致的最小 workspace header 与恢复按钮；任何可渲染应用壳的分支都不得遗漏恢复入口。
4. 点击恢复：将 `isSidebarCollapsed` 设为 `false`，恢复上一份 `sidebarWidth` 和原有 Sidebar 内容状态。
5. 窗口变窄不自动变更状态；用户自行使用可见按钮切换。

### 4.3 视觉与动效

- 项目条使用 `--color-bg-subtle` / `--color-bg-hover`、现有文字和边框 token，圆角与 Sidebar 现有控件一致；不引入黑色品牌方块或新图片资产。
- 双箭头使用现有 Tabler icon 注册表扩充出的左右双 chevron，不把单箭头误作为“上一步”。
- 布局与 DOM 状态立即切换；只对新出现的恢复按钮或工作区内容使用约 120–160ms 的非阻塞淡入，不承诺 Sidebar 的完整滑出动画，避免引入 exiting/entering 状态机。
- `@media (prefers-reduced-motion: reduce)` 下取消或近似取消过渡。动效不应使屏幕阅读器遇到重复或短暂失焦的节点。

## 五、实现设计

### 阶段 1：App 壳层状态和布局

涉及：`src/App.tsx`、`src/styles.css`。

1. 新增极小的 shell preference helper（独立于 view-state/profile 模块），导出 `readSidebarCollapsed()` / `writeSidebarCollapsed()`；`App` 用它初始化 `isSidebarCollapsed`，并通过唯一 `setSidebarCollapsed(next, focusTarget?)` 封装负责 React 状态和写入。
2. 让 `appFrameStyle` 同时提供用于 CSS 的显隐标识，或通过条件 className 切换 `.app-frame.is-sidebar-collapsed`。
3. 将“侧栏区域”与 Workspace 固定为稳定 sibling；仅侧栏区域条件渲染 `<Sidebar>` 与 `.sidebar-resize-handle`，从收起 grid 中删除这两个轨道。正常模型态的 Workspace element identity 不得因显隐改变，不能重挂载、清除选中文件或丢失未保存编辑。`!model` 分支也复用相同的 App 壳布局与展开回调。
4. 不触碰 `handleResetView`、`mutateSelectedViewProfile`、`readLocalViewState` 对 sidebarWidth 的既有行为；只确保它们不会修改显隐 key。
5. `!model` 固定渲染最小的 `workspace → empty-workspace-header → empty-state` 两行结构：header 仅在收起态显示恢复按钮，不复制完整 Toolbar 业务控件，也不因显隐替换 empty-state 根节点。

预期成果：显隐有一个独立 authority，收起后工作区得到完整空间，恢复前的宽度仍可使用。

### 阶段 2：Sidebar 顶部与 Toolbar 恢复入口

涉及：`src/components/Sidebar.tsx`、`src/components/Toolbar.tsx`、`src/components/icons.ts`。

1. 在 `SidebarProps` 新增 `onCollapse?: () => void`；Sidebar 仅在展开态渲染时调用它。
2. 重组 `Sidebar` 顶部 JSX：项目下拉触发器与收起按钮同在第一行；三个管理按钮迁到第二行容器。保持原有 project menu 的 click-outside、`menuitemradio` 和 `aria-checked` 行为。
3. 在 `Toolbar` 的 `toolbar-title` 前增加可选 `onExpandSidebar`。仅在收起态传入并渲染固定尺寸按钮，避免展开态重复占据工具栏空间；为 `!model` 分支提取或复用同语义的空态 header 按钮。
4. 复用 `icons` 注册表，增加语义清晰的双左/双右箭头别名；不在组件内直接导入图标库。

预期成果：两个状态都有固定、可发现、可键盘聚焦的控制入口；项目管理入口不丢失。

### 阶段 3：样式、动效和无障碍

涉及：`src/styles.css`。

1. 为项目第一行、第二行管理区、收起/展开 icon button 新增局部 class，避免修改通用 `.toolbar-action-button` 的所有调用方。
2. 收起态 grid 不保留 resize 轨道；展开态维持现有最小/最大宽度和拖拽行为。
3. 为 `<aside>` 建立稳定 id。所有新按钮必须有稳定 `aria-label`、`title`、`aria-controls` 和可见 focus 样式，并以 `aria-expanded` 准确表达 Sidebar 当前展开状态；反馈不依赖颜色。
4. 焦点编排：App 使用非持久化 `pendingSidebarFocusRef`，仅在用户点击收起/展开时记录目标；由提交后的 `useLayoutEffect` 聚焦并清空该值。点击收起后聚焦当前 workspace header 的“展开侧边栏”；点击展开后聚焦 Sidebar 顶部“收起侧边栏”。首次加载、刷新、项目切换和 Profile 切换不得触发焦点转移。隐藏侧栏时项目菜单、文件树和 resize separator 不得停留在 tab 顺序。
5. 保留 Tab 顺序：展开态为项目切换 → 收起 → 三个管理按钮 → 文件树；收起态从恢复按钮进入既有 Toolbar 或空态 header。

预期成果：参考图的信息层级落在既有设计系统内，同时确保键盘和减弱动效用户可用。

### 阶段 4：测试与浏览器验收

涉及：现有 `tests/data-editor.spec.ts`、`tests/view-state-storage.test.mjs`，必要时新增窄范围测试。

1. 为 shell preference helper 增加窄范围 `node:test`：验证缺失、`"1"`、`"0"`、非法值和写回。`tests/view-state-storage.test.mjs` 只新增隔离断言，证明现有 view-state 读写不读取、不写入 `data-editor:sidebar-collapsed`。
2. E2E 验证展开态两行顶部结构、三个管理按钮仍可用；点击收起后 `.sidebar` 与 resize handle 不存在、Workspace 变宽、Toolbar 恢复按钮可见；点击恢复后侧栏宽度与原有文件树恢复。对已有脏编辑执行一次收起/恢复，断言输入值、选中行与滚动位置仍保持。
3. 刷新、切换项目、切换/加载 View Profile 后验证显隐状态保持。Profile 验收 oracle 为：显隐切换前后没有新增 Profile 保存请求，保存 payload 不含折叠字段，且不出现由显隐引起的 Profile dirty/离开前保存提示；已有 view-state/Profile 写入不得改变新 key。
4. 在已持久化“收起”状态下刷新到 `!model` / Loading 分支，验证空态 header 仍提供恢复入口。
5. 键盘 Tab/Enter 验证两端按钮可操作；检查 `aria-label`、`aria-controls`、`aria-expanded` 和仅由点击触发的焦点转移；刷新到已收起状态时不得抢焦点；在 reduced motion 环境确认状态不依赖动画完成。
6. 浏览器人工检查浅色/深色主题、180px 最小侧栏、默认宽度和较宽侧栏；窄窗口覆盖长文件路径、搜索、状态文字与右侧 Profile/操作同时出现，并保持手动选择、不验收自动收起。

预期成果：持久化、空间回收、功能回归和无障碍都具备可复现证据。

## 六、验收标准

| 场景 | 通过标准 |
| --- | --- |
| 收起 | 点击侧栏顶部双左箭头后，Sidebar 与 resize handle 不在 DOM/grid 中，Workspace 获得释放的横向空间。 |
| 恢复 | 正常模型态 Toolbar 与无模型/加载态空态 header 都固定显示“展开侧边栏”；点击后恢复原宽度、文件树和项目功能。 |
| 顶部层级 | 展开态第一行仅含项目切换和收起，第二行可直接访问三个管理按钮。 |
| 保存范围 | 刷新、换项目、切换 View Profile 后保留显隐；不写入/弄脏 View Profile。 |
| 窄窗口 | 不自动改变用户状态。 |
| 无障碍 | 两端按钮有名称、tooltip、`aria-controls` 和正确 `aria-expanded`；仅点击时焦点会在两端入口间转移，初始化不抢焦点，键盘可操作；无全局快捷键。 |
| 视觉 | 明暗主题均使用现有 token，无新品牌图标；reduced-motion 下无强制动画。 |
| 回归 | 文件树排序、项目菜单、项目管理按钮、侧栏宽度拖拽和 Workspace 未保存编辑均保持原行为。 |

## 七、风险、非目标与回退

| 风险 | 降低方式 |
| --- | --- |
| 仅隐藏 Sidebar 内容导致留下 6px 分隔轨道 | 收起态条件移除 Sidebar 与 resize handle，并由 E2E 测量 Workspace 宽度。 |
| 把显隐混入 View Profile 导致错误 dirty 或跨项目语义变化 | 使用独立 localStorage key，并在 Profile 切换测试中断言其不变。 |
| Toolbar 变窄时恢复按钮挤压标题/搜索 | 浏览器验收中覆盖窄窗口；本次不引入自动折叠或响应式状态机。 |
| 持久化收起后进入 Loading/无模型分支而失去恢复入口 | 在 `!model` 分支复用同语义空态 header；E2E 从已持久化收起状态刷新验证。 |
| 动效造成焦点/可见性竞态 | 状态和 DOM 立即切换，动效仅用于视觉；reduced-motion 禁用过渡。 |
| 条件渲染导致工作区局部编辑、选中或滚动丢失 | 固定 Workspace sibling/实例，并以脏编辑的收起/恢复 E2E 验收。 |
| 以同步 `focus()` 操作尚未挂载的目标按钮 | 使用仅用户触发的 pending focus ref 和提交后 effect；刷新不触发。 |
| 顶部重排损坏项目菜单或管理按钮 | 复用原事件处理和 E2E locator，新增功能只改变容器层级。 |

回退方式：删除 `data-editor:sidebar-collapsed` 可恢复默认展开；不需要迁移、数据回填或修改用户 View Profile。若本次实现需要撤销，可独立移除显隐 key、条件布局和新增入口，而不影响已存在的 sidebarWidth 数据。
