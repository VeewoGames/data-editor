# 描述源文自足与轻量加载优化方案

## 方案概述

目标是让 Data Editor 打开描述时即可阅读、搜索和编辑，把项目语义计算移回用户明确发起的生成动作。推荐模型为：**可读源文自足，稳定引用保留，显式生成统一校验；浏览不执行项目程序。**

范围包括通用编辑器的显示、搜索、自动保存与生成结果接纳，以及项目适配器的源文归一化合同。本文是待确认设计，不是实施授权或当前能力说明。只读核验日期为 2026-10-20，基于含未提交改动的当前工作区；未运行浏览器、计时、生成程序或游戏验收。

结构分为现状证据、方案比较、推荐合同、场景行为、实施顺序和验证。后续阶段依次是：

1. 确认体验取舍及跨仓合同，形成可执行的最小样本规格。
2. 通用产品实现纯源文显示；项目适配器在隔离样本中实现保留可读内文的生成，两边共同验证。
3. 在另行授权的内容范围内补齐旧源文，再切换并删除自动 inspect 链路。

预期成果是普通浏览场景的描述上下文请求和项目子进程均为零；不承诺尚未测得的毫秒收益。本轮不改代码、数据或配置，不迁移组件，不提交或推送，不启动、停止或重启服务，不接管 Nocturnel 主线程的实施与测试。

## 一、问题与当前证据

### 1.1 等待来自哪里

当前主要调用链：

```text
文件加载 → 模板定义
  ├─ 挂载 InlineTemplateField → 每个字符串语言 GET context → Promise.all 后显示
  └─ 无条件搜索上下文 hook → 所有候选行 × 模板 × 字符串语言 → 两个 worker
GET context → 读配置、完整源文件、构建文档并定位行
            → spawn Node 项目 inspect → 再读完整源文件核对 → labels
```

| 已证实行为 | 当前证据 | 影响及限定 |
|---|---|---|
| 每个字段实例独立请求全部字符串语言；当前显示语言不是请求边界 | `src/detail/InlineTemplateField.tsx:89–115` | 中文表格需要等同一字段英文请求完成；任一语言异常会使整组 context 失败 |
| window focus 与 refresh 事件使每个字段重读 | 同文件 `:99–115` | 聚焦可重新出现 pending；取消只忽略结果，没有中止已发出的请求 |
| 搜索预载不检查 query 是否为空；两个 worker 完成全部任务后才安装结果 | `src/detail/useInlineTemplateDefinitions.ts:12–26`；`src/App.tsx:1867,2283` | 与单元格请求不共享，搜索数字标签在预载完成前后可能不同 |
| 描述上下文依赖整份文件 ETag | `src/table/table-columns.tsx:227`；`src/App.tsx:5496–5500` | 自动保存更新 ETag 并触发状态更新，下一次渲染会使搜索与挂载字段重读；普通无关字段保存也在此边界内 |
| 每次合法 context 调用启动独立 Node 进程 | `src/inline-template-context.mjs:10–23`；`src/project-command-action-service.mjs:17–33` | 有整文件读取、解析、进程启动和项目依赖读取成本；请求数不等于已成功启动的进程数，前置失败会减少后者 |
| 项目 inspect 不只返回标签，还解析源文、核验关键词、效果归属和绑定 | `C:/Code/Nocturnel/tools/description/description-command.mjs:9–30`；`description-compiler.mjs:172–186` | 普通显示引入了语义校验成本和失败依赖；这是只读 inspect，**不是生成正式产物** |
| 已支持带内文的 value，但生成后会删除内文 | `src/detail/inline-template-text.mjs:8–12`；项目 `description-compiler.mjs:239–253` | 不能把现有待处理输入分支直接当作已完成的自足源文方案 |

本轮只读计数：`skills.json` 共 **187 行，35 行有 description_sources，70 个字符串语言字段**。在这份候选集、定义已加载且任务未中断的前提下，搜索预载计划发出 70 次请求，即使用户尚未搜索。不是所有 187 行都会请求。

单轮字段请求数为 `Σ 挂载描述字段的字符串语言数`；总量还包括搜索预载和详情面板。实际挂载数取决于可见列、换行/虚拟滚动、详情开关及 React 生命周期，不能用 35×2 直接声称首屏总量。开发模式 StrictMode 亦可能放大副作用；生产环境须单独测量。

ETag 失效、每次请求 spawn、两条读取路径不共享是代码事实。CPU 峰值、首屏延迟、重绘卡顿各占多少，以及服务实际运行哪份构建，均未测量；不能仅凭静态代码声称已证明唯一性能瓶颈。

### 1.2 实时读取到底解决什么

目前它解决的是：**保存的源文缺少可读数值，必须向项目求出标签才能补全阅读**，并能在再次读取时反映机制定义的变化。

它没有证明“所有描述一直有效”：inspect 没有执行生成中的内文与来源一致性比较，也没有持续监听所有项目依赖；focus 刷新不是连续实时保证。源文解析错误还可能阻断原本无关数值的显示。

Frost Nova 的当前源文为整句加 effect/kw/value 引用，value 自闭合；`description_source_values` 只含 `source_kind/source_ref/output`，没有可读文字。这解释了离开适配器后缺数值的原因，不构成修改该技能的授权。

## 二、方案比较与推荐

| 模型 | 普通浏览依赖 | 解决的问题 | 成本和损失 | 建议 |
|---|---|---|---|---|
| A. 保持自闭合标签，增加缓存/去重 | 首次仍需项目 inspect | 减少重复读取 | 缓存失效、跨语言共享与错误状态长期存在；冷开、断连不自足 | 不作为主方案 |
| B. 可读内文常驻源文，显式生成校验 | 已加载文档 + 轻量展示定义 | 从机制上删除普通显示与搜索的项目读取 | 不再自动显示机制刚变更后的最新标签；需补齐旧源文并明确草稿语义 | **推荐** |
| C. 保持动态标签，按需批量读取 | 用户请求时运行项目 inspect | 有明确“查看当前机制”需求时提供实时对照 | 仍需批量协议和来源失败处理，不能替代草稿 | 仅在用户要求实时对照时增补 |

B 不把数字变成新的游戏真值。它只是让作者保存的文字完整可读：草稿显示 140%，机制可以已是 160%。生成时必须拒绝该差异，提供原文、当前来源值和稳定 ref，用户修正草稿后重新生成，不能后台把 140 改成 160。

若明确要求“打开即可看最新机制值”，B 单独不能满足，应采用 C 的显式对照或重新评估动态模型，不能同时宣称零读取和实时正确。C 的最小形式是一次动作对当前选中条目及所选语言发一个请求、一个进程、共读一次依赖，结果只放在对照区；不引入持久标签快照、多层缓存或自动轮询。批量扩展待有实际消费者时决定。

## 三、推荐合同：三个事实，各有一个 owner

### 3.1 数据与写入

| 事实 | 唯一 owner | 保存内容与写入边界 |
|---|---|---|
| 作者意图、可读文字 | 项目数据中的每语言源文 | 用户编辑后普通自动保存；允许未完成或不符合机制的草稿 |
| 稳定关联 | 项目源文 ref 与已有绑定表 | 编辑文字不改 ref；已有绑定保留，不依靠中文/英文标签重新猜关联 |
| 机制数值及规则 | 原机制 owner，经项目适配器读取 | 作者内文不能反向修改机制，Editor 不实现公式、来源推导或关键词业务 |
| 正式描述 | 项目生成器及既有受控写回通道 | 显式生成成功后写正式语言字段和正式绑定；默认隐藏 |

推荐源文形态：

```xml
<effect ref="damage">造成 <value ref="damage">140% 攻击力</value> 物理伤害。</effect>
```

英文同样保存带内文的源文，使用同一个稳定 ref 和共享绑定表；文字不必相同。不新增 `labels`、`display_cache`、`description_preview`、每行有效性布尔值或标签时间戳，不重新维护旧 `description`。

源文内文有意保留“作者当时写下的值”，其存在服务于离线阅读、编辑和差异诊断，不被任何机制计算消费。正式运行时仍使用既有 `<val .../>` 和真实来源绑定。

### 3.2 通用读取与编辑合同

- 文档和模板展示定义足够生成表格、详情和搜索文本。定义只描述 field、语言、表格默认语言及字段保护，普通显示不需要 `inspectCommand`。
- 同一个纯展示投影供表格和搜索复用，投影不能写回 `document.root`。搜索所有已存语言，保持现有跨语言搜索范围，数字只匹配草稿内文。
- 规范 `<value ref>` 的真实内文持续保留；删除“没改过的真实内文序列化成自闭合标签”的分支。不再用“是否有内文”判断待生成状态，因为所有规范源文都有内文。旧自闭合缺值的诊断占位是下文明确的例外，不能把占位保存成作者文字。
- 保留泛用的 `effect/kw/cost` 容器、稳定 ref、转义字面文本及编辑生命周期。Editor 只维护结构，效果合法性、关键词含义与数值等价性属于项目生成器。
- 普通保存沿现有文档 ETag 冲突保护、文件/字段写权限和自动保存调度，不调用项目语义校验。非法或未闭合标记保留可见原文，不能在显示/保存时自动修复。
- 不将本次优化变成整体 contentEditable 重写。输入法、选择区、原生撤销、活动编辑器 flush 与生成结果接纳继续复用现有能力。

### 3.3 显式生成与失效合同

1. 用户选择生成语言，活动编辑器先 flush 并保存当前草稿；保存失败则不启动生成。中文与英文平级，未选草稿不被覆盖。
2. 使用既有 `project-command`：稳定条目定位、已保存文档快照、命令及声明依赖摘要、受控 proposal 写回。一次生成动作处理所选语言，不按每个 value 启进程。
3. 项目生成器解析并校验结构、关键词、稳定绑定、来源有效性、内文与来源标签一致性，以及现有跨语言 ref/effect/cost 规则。已绑定 ref 永远按绑定查来源，不能因内文改成别的值而重定向。
4. 带 ref 的值不匹配时，整次生成失败，报告 `ref + locale + 作者输入 + 当前来源`，保留输入和旧正式产物。用户可手工改为当前来源或另行调整机制；生成器不得擅自改变二者。
5. 成功归一化为**保留转义可读内文的 value**，同时产生既有正式 val。内文只允许按已验证的标签做规范化；不得先覆盖不匹配输入再宣称验证通过。
6. 已绑定关键词的规则保持现有项目合同；无 ref 的新输入不是可靠身份，不能由 Editor 猜绑定。当前编译器支持唯一标签匹配，但本方案不扩大该规则：新绑定的准入须由项目 owner 明确，跨语言有歧义就拒绝。本次切片以已有稳定绑定为前提。
7. 结果提交前再次核对文档和全部声明依赖；变化即拒绝旧结果。保留 `project-command-snapshot` 和 `entry-action-service` 提交锁内复验，不以删除显示请求为由削弱它们。

**关键失败路径**：生成读取 140% 的快照 → 用户继续编辑或机制变为 160% → 旧结果返回。若源文件或声明依赖已变化，服务端拒绝提交；若编辑仍仅在浏览器尚未保存，服务端可能已经合法提交先前快照的产物，前端必须 flush 并保留新草稿，不能以旧生成结果覆盖或标记新草稿已生成。当前 `App.tsx:4311–4332` 在 completed 后回载，`refreshCommandDocument` 提供草稿保留基础；这不等于“任意键入立即阻止服务器写回”，必须分别验证两种时序。

推荐保留最小语义：**已保存输入变化拒旧；未保存新输入拒绝被旧结果覆盖或认定为已生成**。如果用户要求生成期间任何尚未保存的键入也必须阻止服务器写回，需要另行设计提交前握手及断连失败语义，不能假称现有快照保护已满足。本方案不默认增加该协议。

当前服务端使用整文件 ETag，所以生成期间同文件无关行自动保存也可能拒旧。这是既有较保守的正确性边界，本轮不顺带改成字段级合并。**删除显示的 ETag 失效依赖，不等于删除写入的 ETag 保护。**

### 3.4 草稿可读、机制真实、正式有效分别意味着什么

- **可读**：当前保存/编辑的源文能够完整显示；不声明与机制一致。
- **机制真实**：仅由项目适配器在指定检查时读取的机制定义证明；普通浏览不承诺实时核对。
- **正式有效**：正式产物通过生成校验且在提交时依赖未变化。之后源文、机制或编译规则变化，旧结果只是一份历史生成结果，不能自动等同于当前有效。

最小 UI 表达采用字段级说明“作者草稿；生成时核对来源”和已有动作结果提示；重开只显示草稿及“当前未核对”。不建立持久的 valid/dirty/expired 状态机。一次成功提示应写“本次生成已完成”，不要常驻“全部内容最新有效”。

**发布边界不可省略**：仅在 Editor 中显示“未核对”不足以阻止外部构建发布旧产物。项目 owner 必须确认已有正式使用/发布入口有只读一致性门，检查当前源文、绑定、规则与正式输出；没有就补项目侧最小门，失败阻止将该批输出视作当前有效。可复用同一编译核心生成候选并比较正式产物，需同时检验源文内文，不能只比较仍然相同的动态 val 字符串。门在显式验收/构建发布执行，不搬到 Editor 每次打开或保存。

一致性门覆盖本次实际发布的全部语言，而非只调用交互界面当前选择的一种语言。现有编译器对未选语言主要验证既有正式结构/绑定，不能据此宣称它的作者内文也已核对（`description-compiler.mjs:257–278`）。在门内复用编译核心遍历发布范围并检查对应源文；缺失或不一致即失败，不强迫尚未发布的语言先完成。

本轮只定位了生成器和写回保护，没有证明所有正式发布入口已覆盖该门。其接线是后续实施检查点，不能把“当前已完整防止旧结果发布”写成验收结论。无需为此改变游戏运行时行为。

## 四、全场景体验

| 场景 | 推荐行为 | 请求与失败边界 |
|---|---|---|
| 冷打开、重开文件 | 文档和定义返回后直接显示保存的源文 | 不发 context 请求；不等待项目程序 |
| 窗口重新聚焦 | 保持当前文字、选择区与草稿 | 不因 focus 重读标签；既有文档外部变更/保存冲突机制继续负责文件一致性 |
| 中文表格、英文详情、切语言 | 表格按配置默认语言；详情显示选中语言自身内文 | 中文不等待英文；缺翻译明确为空/缺失，不回退到另一语言 |
| 搜索 | 用所有已存语言的本地可读投影，匹配当前草稿 | 不预载/后台补标签；140 草稿不会因机制变 160 自动命中 160 |
| 编辑文字/数字与自动保存 | 保留输入、稳定 ref 和原绑定，保存只反馈落盘状态 | 允许待处理差异；无关保存不会重载任何描述来源 |
| 外部机制变化 | 草稿仍可读，下一次生成或正式验收发现差异 | 不声称立即发现；用户需要即时对照时另选方案 C |
| 显式生成 | 所选语言统一校验、成功后受控写回 | 原子失败，不只写成功的一部分语言 |
| 生成中继续编辑 | 输入与自动保存继续工作，依赖变化拒旧；回载保留更新草稿 | 不锁整页；保留既有较保守的整文件冲突边界 |
| 断连、inspect/生成失败 | 已加载源文继续阅读和编辑；保存失败清楚提示 | 未保存输入仅按现有会话保护，不承诺关页后持久；不引入 localStorage 草稿副本 |
| 损坏标记、失去绑定 | 保留可见原文，生成给定位诊断 | 不吞错、不凭显示标签修复关联 |

复制粘贴与撤销：同一条目/字段内（包括跨语言）沿现有结构化剪贴板携带 ref 和容器，完整片段复制、剪切、移动、撤销需往返保真；部分跨边界复制按现有规则明确拒绝。跨条目、跨字段及外部纯文本粘贴不冒用原 ref，保留文字并提示“关联未携带，需生成检查”。该提示是拟新增的必要反馈，当前实现不能视为已具备。本轮不扩展跨作用域自动映射。

纯文本中看起来像 `<value ref=...>` 的控制标签不能因粘贴、保存、重开而自动获得身份；应保留为转义字面文本。作者输入的未绑定数字表达式仍是待生成检查的文字，不由 Editor 猜绑定。需单独验证外部粘贴，不能拿已有“已转义源文”测试替代。切语言和切行前 flush，覆盖鼠标、键盘和输入法组合态；后台响应不能重绘正在编辑的 DOM。

## 五、旧语法、迁移和删除范围

不需要新建数据模型，也不需要复制第二份源文，但**已有自闭合 value 缺内文，必须有受控补齐动作**，否则无法兑现离开适配器仍完整可读。

推荐在后续已授权内容集合做一次补齐：项目适配器按现有 ref 查真实来源，为每种语言填入内文；禁止改 ref、binding、effect/kw/cost 结构和机制字段。已有带内文草稿逐字保留，差异不能被“迁移”消除。未知来源、损坏结构或缺语言标签停在报告中，不编造值。仅用 fixture 证明路径后，再由主线程决定实际条目清单。

新模型遇到未补齐的自闭合 value，显示明确的“缺可读源文：ref”占位，允许保留编辑；**不自动 inspect、不自动写盘、不回退到旧 description**。这只是错误诊断入口，不能把占位当作生产切换验收成功。

诊断占位不属于作者源文：无关文字编辑、结构化复制、撤销与保存必须保留该节点原始自闭合字节；只有受控补齐或用户实际编辑该值才产生内文。不得把“缺可读源文”写成 value 内容。可用现有 DOM 原始值/来源标记辨别，不新增持久字段。纯文本复制可以呈现缺值提示，但提示不得在后续粘贴中被识别成有效数值。

**全局切换门**：所有受影响的实际消费者（含其他项目、其他组件和语言）均已具备自足源文，且旧接口已无必要消费者，才能上线全局删除。限定组件补齐只证明局部可行，不满足这个门。未获其余范围授权时，停在隔离切片，生产继续现有路径；不扩大迁移范围，也不引入长期逐行双模式开关。补齐工具与新 compiler 可先在隔离副本验证，禁止混装生产新旧 serializer。

删除候选：

- `InlineTemplateField` 的 context 请求、pending/error/generation 读取状态、focus 标签刷新。
- `useInlineTemplateSearchContexts` 和 App 的搜索上下文预载。
- 表格/详情为显示传递的 `contextRevision/documentEtag`，以及仅服务标签重读的事件路径。
- `/api/inline-template-context` 和 `inspectCommand` 展示配置，在确认无剩余消费者后删除。保留轻量 definitions 接口。

**不能一起删**：生成后的文档回载/接纳通知、活动草稿保护、写权限、文档 ETag、项目依赖快照、锁内复验、提交恢复。现有 refresh 事件同时承载标签刷新和成功生成接纳，应去掉前者、保留或直接传递后者；不能一把删事件导致规范化结果无法安全接纳。

如果最后仍有获准的显式对照消费者，再为它保留最窄 inspect 能力；不为假设性未来保留通用缓存、常驻进程或多模式配置。
