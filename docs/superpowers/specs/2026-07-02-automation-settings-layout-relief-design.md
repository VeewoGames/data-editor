# 方案概述

## 1. 总体目标和范围

本方案用于优化 `Automation Settings` 弹框的可读性与视觉密度，解决当前界面“过窄、过挤、信息堆叠”的问题。  
本轮只调整前端结构与样式，不改动 `automation profile` / `automation bindings` 的数据模型、保存逻辑、校验规则和运行链路。
界面文案默认中文化：除 `Rule Id / Label / Icon / Skill / Target Files / Target Collections` 这类字段名、ID 语义和必要技术名词外，其余状态、说明、按钮和提示文案统一改为中文。

## 2. 各阶段任务概要

### 阶段一：布局重排
- 主要工作：扩大弹框宽度，重组顶部摘要区、告警区、规则卡片和底部操作区
- 预期成果：用户在桌面端打开弹框后，同屏压迫感明显下降
- 执行顺序：先改容器与分区，再改字段排布

### 阶段二：规则卡片减压
- 主要工作：把单条 rule 卡片拆成更清晰的分区，降低删除按钮视觉权重，提升字段与选项区留白
- 预期成果：单条 rule 更像“配置卡片”，而不是挤在一起的一长段表单
- 执行顺序：先调结构，再补细节样式

### 阶段三：验证与收口
- 主要工作：确认新增动作、校验提示、保存禁用和详情动作链仍正常
- 预期成果：布局变轻，但行为不变
- 执行顺序：typecheck、e2e、浏览器回看

## 3. 整体结构框架

- 顶部：保留标题 + 紧凑摘要
- 中部：`Validation issues` 作为更轻的状态块
- 主体：每条 rule 卡片拆成基础信息区、target 区、选项区
- 底部：弱化但清晰的 sticky footer

---

# 设计目标

1. 弹框宽度提升到当前约两倍，让桌面端编辑区有真正的横向呼吸空间。
2. 让摘要信息、错误提示、rule 配置三层内容在视觉上可快速区分。
3. 让用户一眼知道“我在看状态、我在编辑规则、我在做保存操作”，而不是看到一整块连续表单。

# 方案细节

## 1. 弹框容器

- 将 `automation-settings-dialog` 的宽度从当前约 `760px` 提升到接近 `1400-1500px` 的桌面宽度上限。
- 保留高度限制与滚动，但让内部内容不再依赖窄列换行。
- 底部操作区继续 sticky，但减轻边框和压迫感，让它更像页面底栏而不是堵在表单尾部的工具条。

## 2. 顶部摘要区

- `Nocturnel` 状态摘要保留，但压缩成更紧凑的状态卡。
- `Storage` 从完整信息卡降级成次级说明块，标题与说明改为中文表达，降低视觉抢占。
- `Validation issues` 保持可见，但改成更薄、更像状态提醒的告警区，而不是大面积高权重错误面板；标题与提示内容改为中文。

## 3. Rule 卡片

- 每条 rule 改成更明确的三段：
  - 基础信息：`Rule Id / Label / Icon / Skill`
  - 目标范围：`Target Files / Target Collections`
  - 运行选项：启用开关、binding 开关、payload 复选项
- 基础信息保持双列，但增大行间距和字段内边距。
- `Target Files / Target Collections` 使用更宽、更稳定的纵向区域，减少与上方输入框挤在同一视觉层。
- 删除按钮改成更轻的次级危险操作，仍然可见，但不再作为卡片最高权重点。

## 4. 操作区

- `新增动作` 与 `Rules` 标题保持同一行，但整体更松，避免贴边。
- `关闭 / Save Automation` 与内容区拉开，并保证保存按钮在视觉上清晰但不过分厚重；其中非字段类按钮文案改为中文，例如 `Save Automation -> 保存自动化设置`。
- 当存在本地校验问题时，`Save Automation` 继续禁用，不改变当前行为。

## 5. 文案规则

- 保留英文的范围：
  - 字段名与字段值输入语义：`Rule Id`、`Label`、`Icon`、`Skill`、`Target Files`、`Target Collections`
  - 必要技术标识：`Codex`、`automation profile`、`binding`
- 改为中文的范围：
  - 弹框标题、分区标题、状态摘要、空状态、错误提示、保存成功提示、加载提示、按钮文案
  - 复选项说明文案，例如 `Enable rule`、`Include current row`
- 目标效果：
  - 用户看到的是“中文产品界面 + 少量必要技术字段”，而不是“中英混杂的管理面板”

# 不做项

本轮明确不做以下内容：

- 不改成多步骤或 tab 式配置流程
- 不引入新的字段编辑器类型
- 不改变本地校验逻辑和错误语义
- 不改变 `automation-profile` / `automation-bindings` 的 API 或持久化方式

# 验证标准

1. 用户在桌面端打开 `Automation Settings` 时，能够明显感知宽度增加与留白增加。
2. `Validation issues`、rule 卡片、底部操作区不再形成连续的拥挤长表单。
3. 点击 `新增动作` 后，新增卡片和校验提示仍能正常出现。
4. 现有 `Automation Settings` 相关 e2e 继续通过。
