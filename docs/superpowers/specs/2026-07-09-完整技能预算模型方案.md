# 完整技能预算模型方案

## 方案概述

### 1. 总体目标和范围

本方案目标是为 Nocturnel 的玩家主动技能建立一套完整、可审计、可迁移的技能预算模型，解决当前“能说明 AP 档位和设计理由，但看不清具体预算消耗是否合理”的问题。

本方案不直接替代实机平衡，也不把技能预算做成精确战斗模拟器。它的定位是作者侧和审计侧的预算账本：让每个技能都能清楚说明“可用预算从哪里来、效果消耗了多少、通过什么代价支付、是否超过容差、哪些项需要实测校准”。

第一阶段建议只覆盖玩家主动技能，包括 `Attack`、`Spell`、`Empower`、`Minion`、`Avatar` 五类技能。敌人、Boss、装备词缀、辅助符文可复用同一思想，但不应在第一阶段强行并入，否则模型会过早膨胀。

### 2. 各阶段任务概要

| 阶段 | 主要工作 | 预期成果 | 执行顺序 |
|---|---|---|---:|
| A. 建模 | 定义预算单位、可用预算、消耗预算、支付项、容差和红线 | 一套统一预算账本口径 | 1 |
| B. 标定 | 用现有稳定技能校准 AP、伤害、范围、控制、异常、护甲、位移等预算项 | 初版预算分值表 | 2 |
| C. 模板接入 | 更新技能设计指南和开发文档模板 | 每个技能文档都有预算拆账区 | 3 |
| D. 评分衔接 | 将预算账本接入“AP 与数值预算”评分维度 | 评分依据可回看、可复核 | 4 |
| E. 样本迁移 | 先迁移 10-20 个代表技能，再决定是否批量迁移 | 模型校准反馈和迁移规范 | 5 |
| F. 工具化 | 可选开发预算校验脚本或表格 | 自动发现超预算和缺账项 | 6 |

### 3. 整体结构框架

```text
技能字段
  -> 效果拆解
  -> 可用预算账本
       AP 基础预算
       冷却返还
       资源支付
       条件/风险返还
       投放门槛返还
  -> 消耗预算账本
       伤害/治疗/护盾
       空间/安全
       控制/异常/减益
       位移/召唤/部署
       构筑接口
       复合收益溢价
  -> 容差与红线
  -> AP 与数值预算评分
  -> 技能开发文档
```

## 一、当前问题判断

当前问题不是单纯由文档压缩造成的。文档压缩确实把 `skill_axe_throw` 里一些预算解释压短了，但更深层的原因是现有规则只有“锚点 + 修正因子 + 评分维度”，没有统一预算点账本。

现有资料已经具备三类基础：

| 已有基础 | 来源 | 当前能力 | 缺口 |
|---|---|---|---|
| AP 效率与修正因子 | `战斗数值平衡手册 2.0（AI 专用）` | 能判断远程、多目标、控制、条件、风险、冷却如何影响效率 | 缺少逐项预算点，不方便解释“多消耗了多少” |
| AP、冷却、功能折扣 | `技能设计指南（AI 专用）` | 能判断技能属于哪个 AP 档和应由什么代价支付功能收益 | 缺少量化账本，容易写成自然语言 |
| 评分结构 | `技能(玩家)品质标准（AI专用）` | 要求完整评分，AP 与数值预算占 20 分 | 评分可以给结论，但不能自动解释预算消耗过程 |

因此完整修复方向应该是新增“技能预算账本层”，而不是继续往开发文档里堆更多自然语言说明。

## 二、核心模型

### 2.1 预算单位

建议引入 `BU`，即 `Budget Unit / 预算点`。

初版标定采用易读规则：

| AP | 基础预算 BU | 定位 |
|---:|---:|---|
| 0 | 0-60 | 被动、反击、战略资源，必须有严格条件 |
| 1 | 100 | 功能性、辅助、快速动作 |
| 2 | 200 | 标准输出、标准战术技能 |
| 3 | 300 | 强力手段 |
| 4 | 400 | 全回合大招、结构级技能 |

这个数值不是最终平衡真值，而是作者审计刻度。选择 `1 AP = 100 BU` 的理由是可读性高，能让“10-20 BU 的小偏差”和“50+ BU 的结构性超支”直观看出来。

### 2.2 总公式

```text
可用预算 = AP基础预算 + 冷却返还 + 资源支付返还 + 条件/风险返还 + 投放门槛返还

消耗预算 = 核心效果预算 + 空间安全预算 + 功能预算 + 构筑接口预算 + 复合收益溢价

预算差额 = 可用预算 - 消耗预算

预算结论 =
  预算差额 >= 0：通过
  预算差额在 -15% 容差内：边界通过，必须标记待数据
  预算差额低于 -15%：需修改
  命中红线：不通过，不能用其他维度抵消
```

`15%` 容差来自现有“同类型、同 AP、相近环境技能 AP 效率偏差应控制在约 15% 内”的规则。预算模型不改变这个阈值，只把它用于账本判定。

### 2.3 可用预算账本

| 来源 | 初版规则 | 说明 |
|---|---:|---|
| AP 基础预算 | `AP * 100 BU` | 主要预算来源 |
| 冷却 0 | `+0 BU` | 仅受 AP 限制，不提供额外预算 |
| 冷却 1 | `+10% 到 +15% AP基础预算` | 每回合限一次，适合轻量功能支付 |
| 冷却 2 | `+20% 到 +30% AP基础预算` | 标准战术技能的主要返还档 |
| 冷却 3 | `+35% 到 +45% AP基础预算` | 强力技能或主动增益 |
| 冷却 4-5 | `+60% 到 +80% AP基础预算` | 整场 1-2 次的大招或结构级技能 |
| 法力支付 | 按技能类型单独标定 | 第一阶段只记录，不建议先硬编码 |
| 条件限制 | `+10% 到 +40%` | 条件越难兑现，返还越高 |
| 自我风险/近身风险 | `+10% 到 +25%` | 与现有风险修正因子一致 |
| 构筑门槛 | `+5% 到 +20%` | 仅当输入标签确实限制可用构筑时生效 |

冷却返还必须防止重复计算。例如 `4 AP` 大招本身已默认需要 `4-5` 冷却，不能再把冷却返还当成免费超额奖励；此类技能应有单独红线检查。

### 2.4 消耗预算账本

#### 2.4.1 核心数值效果

| 效果 | 初版估值方式 | 说明 |
|---|---|---|
| Attack 伤害 | 以同 AP、同武器/同层级伤害预算折算 BU | `AD x weapon_damage_ratio + base_damage` |
| Spell 伤害 | 以同 AP、同层级 Spell 伤害预算折算 BU | 同时记录法力支付 |
| 治疗 | 参考 1 AP L1 `5 HP`、L3 `12-15 HP` | 需区分战斗中即时治疗和延迟治疗 |
| 临时护甲 | 参考 1 AP L1 `4-5`、L3 `12-16` | 临时护甲价值高于战斗护甲 |
| 战斗护甲 | 约临时护甲 `60%-70%` | 长期收益但即时防御较弱 |
| 控制 | 约 `0.6 倍伤害 AP 效率` | 控制会减少敌方行动价值 |
| 位移 | 2-3 格作为 1 AP 功能锚点 | 不随层级线性膨胀 |

#### 2.4.2 空间与安全收益

| 项 | 建议 BU | 说明 |
|---|---:|---|
| 短距远程 `sight 2-3` | 15-30 | 让近战构筑获得安全出手点 |
| 标准远程 `sight 4-5` | 30-50 | 接近远程基础攻击的安全收益 |
| 长距/无风险远程 | 50+ | 需严格结合伤害折减和目标限制 |
| 小范围多目标 | 25-60 | 还要按目标数估算总收益 |
| 稳定多目标/大范围 | 60+ | 通常需要显著伤害折减或高冷却 |

空间收益不能只看范围字段，还要看技能是否让原本需要冒险的构筑绕开了风险。`skill_axe_throw` 的 `sight 3` 对弓手不是高价值，但对近战武器构筑是明确价值。

#### 2.4.3 功能与状态收益

| 项 | 建议 BU | 说明 |
|---|---:|---|
| 轻量标记/短期接口 | 10-25 | 只改变后续构筑条件，不直接增伤 |
| 单体 1 回合轻减益 | 20-35 | 例如轻量命中、防御或速度影响 |
| 单体 1 回合中等减益 | 35-55 | 例如 `armor -20% 到 -30%` |
| 强控制 | 60+ | 应显著降低伤害或提高冷却 |
| 持续 2+ 回合异常 | 40+ | 按持续时间和兑现概率递增 |
| 稳定资源生成/转化 | 30+ | 取决于资源稀缺度和循环潜力 |

功能收益要区分“数值等价”和“接口价值”。破甲、标记、异常、资源、部署物经常不是当回合立即兑现，但会打开后续收益，因此必须入账。

#### 2.4.4 构筑接口与复合收益

| 项 | 建议 BU | 说明 |
|---|---:|---|
| 单一标签接口 | 5-10 | 只提供标签连接，不改变输出结构 |
| 稀缺机制入口 | 10-25 | 奖励池中少见的功能入口 |
| 同时服务输出和构筑 | 10-20 | 例如伤害技能同时提供关键 debuff |
| 复合收益溢价 | 消耗预算的 5%-20% | 多个效果互相强化时追加 |

复合收益溢价很重要。一个技能如果同时造成伤害、远程安全、破甲，并且这些效果服务同一套输出链，就不能只把三个单项相加后认为结束；需要追加 5%-20% 的复合收益溢价。

## 三、预算结论分级

| 结论 | 条件 | 文档写法 | 后续动作 |
|---|---|---|---|
| 通过 | `消耗 <= 可用`，且无红线 | 写入预算通过 | 可进入评分 |
| 边界通过 | 超支不超过 `15%`，且理由清楚 | 写入待数据 | 需要样本或实机验证 |
| 需修改 | 超支超过 `15%` | 写明应削哪一项 | 调 AP、冷却、倍率、范围、条件 |
| 红线不通过 | 命中硬红线 | 不得用总分抵消 | 回炉重写 |

预算结论必须先于最终评分。评分记录可以解释设计质量，但不能用“职责清晰”“文本好”去抵消预算红线。

## 四、与评分系统的衔接

`AP 与数值预算` 仍保留 20 分，但评分依据应从自然语言改为账本驱动：

| 档位 | 得分区间 | 预算账本条件 |
|---:|---:|---|
| 5 | 17-20 | 账本完整、预算通过、样本对比充分、无待数据关键项 |
| 4 | 13-16 | 账本完整、预算基本通过，存在可接受待数据 |
| 3 | 9-12 | 账本能解释主要效果，但有明显不确定或轻微超支 |
| 2 | 5-8 | 账本缺项或超支明显，但可通过调参修复 |
| 1 | 1-4 | 预算结构不成立或命中严重上位风险 |
| 0 | 0 | 红线不通过或字段不足以估值 |

这样可以保留用户要求的完整评分过程，同时让评分前方多一个“预算账本”。评分保留完整内容，预算账本负责解释分数依据。

## 五、开发文档模板调整

建议技能开发文档的前半部分调整为：

```markdown
## 技能摘要

## 正式规则

## 预算账本

### 可用预算

| 来源 | BU | 依据 |

### 消耗预算

| 效果项 | BU | 依据 |

### 预算结论

- 可用预算：
- 消耗预算：
- 差额：
- 判定：
- 待数据：

## 风险与待确认

## 评分结论摘要

## 完整评分记录

## 附录：开发记录
```

关键变化是把预算账本放在评分之前。读者先看技能为什么没有超预算，再看完整评分过程是否合理。

## 六、skill_axe_throw 示例

以下是按初版 BU 模型对 `skill_axe_throw` 的示范拆账。数值用于验证模型可读性，不代表最终标定。

### 6.1 可用预算

| 来源 | BU | 依据 |
|---|---:|---|
| 2 AP 基础预算 | 200 | 标准 Attack / 战术技能 |
| 1 回合冷却返还 | 25 | 约 12.5% 基础预算；每回合限一次 |
| melee/weapon 输入门槛 | 10 | 限定近战武器构筑，不是全职业通用远程 |
| 合计 | 235 |  |

### 6.2 消耗预算

| 效果项 | BU | 依据 |
|---|---:|---|
| `0.75 AD` 单体物理伤害 | 150 | 低于 2 AP 标准满额输出，用于支付附加功能 |
| `sight 3` 短距远程安全 | 25 | 近战构筑获得安全出手点 |
| `armor -25% / 1 回合` | 40 | 单体 1 回合中等减益，打开后续物理输出窗口 |
| `projectile/physical/armor` 接口 | 10 | 提供 warrior/general 稀缺 armor 入口 |
| 复合收益溢价 | 10 | 伤害、远程安全、破甲服务同一输出链 |
| 合计 | 235 |  |

### 6.3 示例结论

```text
可用预算：235 BU
消耗预算：235 BU
差额：0 BU
判定：预算通过，但属于边界稳定型技能
待数据：warrior/general 同池实机比较；armor -25% 实际收益
```

这个示例解释了为什么原先“2 AP、1 CD、0.75 AD、sight 3、armor -25%”看起来合理：不是因为文案说合理，而是因为伤害折减、短冷却限制、短射程和构筑门槛共同支付了远程安全与破甲收益。

如果后续实机发现破甲收益偏高，优先调整项应是：

| 调整项 | 影响 |
|---|---|
| `armor -25%` 降到 `-20%` | 降低功能预算 5-10 BU |
| `cooldown 1` 提到 `cooldown 2` | 增加可用预算，但会改变节奏定位 |
| `ad_ratio 0.75` 降到 `0.65-0.70` | 降低核心伤害消耗，保留功能定位 |
| `sight 3` 降到 `sight 2` | 降低安全收益，但手感可能变差 |

## 七、红线与防滥用规则

完整预算模型必须保留红线，不允许全部用 BU 抵消。

| 红线 | 原因 |
|---|---|
| 4 AP 技能冷却低于 3 回合 | 现有数值手册明确风险 |
| 同 AP、同类型效率超过约 15% 且无代价 | 严格上位风险 |
| 免费动作稳定输出或稳定控制 | 破坏 AP 经济 |
| 远程、多目标、控制没有任何支付 | 复合收益失控 |
| 未立项机制被当成已有机制估值 | 系统真实性不成立 |
| 评分记录与预算账本矛盾 | 文档不可审计 |

## 八、落地文件建议

| 文件 | 动作 | 内容 |
|---|---|---|
| `战斗数值平衡手册 2.0（AI 专用）.md` | 新增章节 | `技能预算 BU 模型` 和初版分值表 |
| `技能设计指南（AI 专用）.md` | 更新模板 | 将 `预算说明` 改为 `预算账本` |
| `技能(玩家)品质标准（AI专用）.md` | 更新评分依据 | `AP 与数值预算` 改为账本驱动评分 |
| 技能开发文档模板 | 更新结构 | 预算账本前置，完整评分保留 |
| 代表技能文档 | 试迁移 | 先迁移 10-20 个技能校准分值 |

不建议第一步直接批量改所有技能文档。预算模型需要先经过样本校准，否则看似完整，实际会把未校准的分值固化。

## 九、样本校准计划

建议选择以下样本组做第一轮校准：

| 样本组 | 目的 |
|---|---|
| 基础 Attack | 校准 1 AP、2 AP、3 AP 伤害 BU |
| 远程 Attack | 校准 `sight` 和远程安全 BU |
| armor 技能 | 校准护甲削减、护甲穿透、破甲接口 BU |
| 控制技能 | 校准控制和伤害折减关系 |
| 位移技能 | 校准位移格数、目标限制和冷却关系 |
| Spell 技能 | 校准法力支付与法术伤害 BU |
| Minion / deployable | 校准持续实体、继承折损、行动节奏 |

每组至少 3 个技能。少于 3 个样本时，只能给临时分值，不能把表格写成最终标准。

## 十、执行建议

推荐执行顺序：

1. 先确认 `BU` 模型作为方向成立。
2. 建立 `技能预算 BU 模型` 指南章节。
3. 用 10-20 个代表技能校准初版分值表。
4. 更新技能开发文档模板，但保留完整评分记录。
5. 迁移 `skill_axe_throw`、`skill_throw_knife`、`skill_thrust`、`skill_armor_break` 等同池样本。
6. 根据迁移反馈再决定是否做脚本化校验。

## 十一、推荐结论

建议采用完整预算模型，但不要一次性把它做成强约束自动化系统。

第一版应是“人工可审计账本 + 样本校准表 + 文档模板”，先解决设计师和审计者看不清预算消耗的问题。等代表技能迁移后，再把稳定规则抽成脚本检查。这样既能补齐当前机制缺口，又不会因为初始分值未校准而制造新的伪精确。
