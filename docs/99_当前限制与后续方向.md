# Data Editor 当前限制与后续方向

## 概述

本节只记录当前代码已经暴露出来的限制、边界和后续演进主题。

## 当前限制

### 文本与本地化

仓库里仍有一部分界面文案存在编码历史问题，特别是某些组件中的中文字符串。这不影响机制本身，但会影响实际显示质量。

### 顶层编排较重

`src/App.tsx` 仍承担文件与配置加载、服务恢复、relation/backlink 数据准备、保存流程及多个对话框状态等编排职责，许多横切行为集中在一个入口中。

### relation 配置入口仍以字段级为主

当前 relation 的显式配置主要通过字段入口完成。更复杂的嵌套路径维护虽然有底层支持，但可发现性仍然不强。

### 单机使用假设明显

系统以本地、单用户优先。它支持多项目和多个数据源，但不包含多人协作、权限控制或远程并发一致性处理。

## 已知边界

- 项目级配置和个人视图配置必须严格分开理解。
- backlink 是派生视图，不是业务字段。
- primary key 候选分析不等于主键正式配置。
- `npm run open` 是正式打开路径，`npm run dev` 仅用于开发。
- 数据文件默认 direct-write，不提供本地 `.bak` 备份层。

## 后续演进主题

- 文案编码和界面文本统一清理。
- `App.tsx` 的编排职责拆分。
- 更完整的嵌套 relation 配置体验。
- 更强的主键变更批量维护能力。
- 更细的测试夹具和端到端覆盖。
- 更清晰的错误状态与诊断面板。

## 维护规则

- 正式文档只保留已经实现且可由代码、测试或运行链路验证的事实。
- 设计讨论和一次性实施计划可在任务期间使用；完成后应把长期有效内容压缩回正式文档集，并清理历史材料。
