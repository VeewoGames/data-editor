# 性能优化中间版本交付清单

## 方案概述

本次收敛长期性能任务，目标是交付一个范围固定、可以结束的中间版本，而非继续等待所有卡顿消失。范围分为：**第一中间版的前端累积修复、单独待整合的无历史后端、延期功能、明确不采用的实验**。先冻结已有成果和来源，再完成一次有限整合及兼容验收，最后提交正式激活决定；不再新增性能原型或重跑长期性能对照。

推荐的第一中间版为 **M1「表格编辑基础修复版」**：以 `frontend-row-projection-validation` 的实际浏览器依赖为主体，保留原编辑操作和自然行高规则。中间版接受滚动、完整保存耗时仍有遗留问题，不能命名为“性能全面修复版”。本文件是发布范围与验收合同，**不是已经构建、合并或激活的版本**。

**当前最重要的事实：没有一个隔离目录可以直接整体覆盖正式项目。** 本轮已核验两个有效来源共865个文件，冻结漂移为0；形成正式树差异及浏览器运行代码清单。正式运行入口仍指向根 `server.mjs`、根 `dist` 和根 `recovery-bridge.mjs`，不是这些候选目录。进程路径只能说明入口，不能证明进程内代码与磁盘摘要完全相同。

## 二、不能直接合并的原因

1. **候选存在混装。** 357/508同路径有67项内容不同；其目录各自含旧的另一侧源码。冻结全清单相对当前正式树分别有84项、152项不同或缺失，包含构建/测试等，均不是可直接发布的文件数量。正式树有246个Git状态条目，不能重置、整体覆盖、默认暂存全部，也不能以Git HEAD替代当前来源。
2. **前端构建仍依赖隔离路径。** React Virtual通过 `../virtual-dependencies` 的Vite alias及TypeScript paths接入；package/lock未正式声明。整合时只做一次打包适配：固定已测React Virtual 3.14.23 / Virtual Core 3.19.8，消除task相对路径并重建。旧产物SHA不冒充新产物SHA。
3. **存在共享模块。** `document-model.mjs`、`multiselect-config.mjs`、`view-config.mjs`等同时影响前后端；必须逐一处理owner及语义，不能按复制先后选择。
4. **508有功能缺口。** 合法project-write、followup/create以及旧proposal/ack/exact等入口仍有安全拒绝。绑定process的项目删除直接503，保留的终态run也可能阻止项目删除。这些不是性能成功，不能未经接受静默带入正式产品。
5. **当前正式后端仍有历史读取。** 只整合前端时，根server的journal/history计算不会自动消失。不能把M1前端包宣称为“整版无历史目标完成”，也不能为了兼容恢复508里已经删除的历史计算。

## 三、明确排除与延期

**不进入M1，也不再扩大复测：** precommit frame、独立绝对grid行布局、idle flush、HeaderMemo、CSS布局消融、未通过的Names/Context/缓存/私有快照等后继实验。它们有诊断或安全价值，但稳定收益未过门；保留源码及正负证据，不删除、不混入有效357。

**延期且不阻塞M1包形成：** 剩余滚动布局热点、局部保存/完整请求协议、首次整root快照工作、未复现的永久saving、完整project-write互斥、其他未闭合自动化及真实IME。未获回复的“屏外列不再维持行高”A/B不在本版实施，不改变既有行高显示规则。

**仍是数据安全硬门，不能延期：** 已确认内容、完整源数据及引用、当前路径/权限/只读、ETag/版本冲突、并发写和原子替换；编辑交互不变，Data Editor无项目专属逻辑。不能用丢失草稿的许可放松这些要求。

## 五、后端的独立发布取舍

后端508不能整体直接发布。若要将“正常计算不读取历史”作为本次**整版激活的硬条件**，必须同时交付508正常路径依赖闭包，并单独确认其余现有入口如何交付：

- 接受明确列出的自动执行/项目管理能力暂不可用，形成范围受限的编辑版；这是功能取舍，需要用户明确决定，不能从“需要中间版”推定。
- 保留现有合法能力，另做有限的后端修复/整合门；不重开滚动研究、不恢复历史计算，不把503当成功。

**本次未替用户选择任何一种。** 推荐现在先把前端中间包整合和冻结完成；后端取舍单列，不再让其影响前端包形成。若暂搭配正式旧后端，只能称前端阶段交付，不能宣称满足整版无历史合同。前端包形成与可正式激活必须区分。
